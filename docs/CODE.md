# CODE.md — 代码规范

**这份文件管"写代码时怎么下笔"**：文件与函数多大算大、命名照哪一套、错误怎么返回、
日志写什么、注释写什么、提交信息怎么写、什么时候允许加依赖。

⚠️ **它不管"这个坑为什么存在"**——那些在本项目的**唯一纪律台账** `AGENTS.md` 里
（变异验证、沙箱纪律、gpui 的各种静默失效、发版流程…），本文件只在需要时**指路**，
**不复述**（复述一次就多一处会漂的真源）。档位数值同理：视觉六类数值只在
`docs/UI-DESIGN-v4.md`。

---

## 1. 文件与模块布局

- **依赖方向是单向的：`gui` → `crates/core`**，`core` 不认识 gpui。
  core 里出现 `gpui` / `Theme` / `Entity` 这类词就是走错层了。
- **一个文件一件事**。`gui/src/` 现在的分工：`shell`（壳与根渲染）、`state`（应用状态）、
  `ops`（异步操作的编排与进度搬运）、`tokens`（视觉档位）、`widgets`（共用构件）、
  `panels` / `sidebar` / `repo_head` / `space_tab` / `history_tab` / `changes` /
  `readme_tab` / `overview`（各页）、`dialogs/*`（对话框）、`os` / `diag` / `git` 的 GUI 侧包装。
  **新写一个功能先问它属于哪一个**，不要往 `shell.rs` 里加。
- **尺寸红线**（2026-10-12 按实测定的，取"该拆了"的信号，不是硬指标）：
  - 单个源文件 **> 1000 行** ⇒ 拆分候选（现在 6 个文件超线，见 `docs/CODE-AUDIT.md` §1）
  - 单个函数 **> 150 行** ⇒ 拆分候选（现在 4 个函数超线，同上）
  - 同一段逻辑**出现第二遍** ⇒ 就地抽成函数，不等第三遍（本项目的"两份拷贝"
    已经出过编译期查不出、只有实机帧上看得见的事故：侧栏与检视抽屉、
    `dialogs/init.rs` 与 `dialogs/purge.rs`）
- **模块只有 `#[cfg(test)]` 里的测试可以住在同文件**（core 与 gui 都是这个写法），
  不另开 `tests/` 目录。
- **行尾（CRLF / LF）不是仓库级常量，别按扩展名推断**（2026-10-12 实测同一棵树上：
  `crates/core/src/net.rs` 是 CRLF 1083 行 / 裸 LF 0，而 `gui/src/tokens.rs` 是裸 LF 1296 行 /
  CRLF 0、`gui/src/shell.rs` 裸 LF 2192 / CRLF 0）。
  ⇒ **按字节改文件的脚本，先量目标文件此刻的行尾再写**；量反了只会得到一句
  "锚点 0 次"，白跑一轮（这个坑整轮变异都没跑成，见 `AGENTS.md` D92 那一族）。
  也不要顺手"统一行尾"——那是一次覆盖全工作树、需要专门一轮验证的动作。

## 2. 命名

下面这套**不是新定的，是把现有代码里已经成立的习惯写下来**——照它写，
不要另起一套（两套命名和"同一属性两个名字"是同一种病）。

| 形状 | 含义 | 现成例子 |
|---|---|---|
| `run_*` | 一个会 spawn 到后台、有进度可看的操作入口 | `ops::run_sync`、`clone::run_clone`、`run_repo_cmd`、`net::run_net_op` |
| `*_of` | 纯派生判据（从状态算出结论，无副作用，可单测钉真值表） | `route_of`、`badge_kind_of`、`badge_is_neutral` |
| `fs_meta` / `fs_sec` / `fs_body` / `fs_title` / `fs_head` / `fs_num` | 字号，**函数**不是常量（跟 `UiScale` 走） | `gui/src/tokens.rs:388-410` |
| `r_lg(t)` / `r_xl(t)` | 跟主题走的圆角，**函数** | `gui/src/tokens.rs:424-430` |
| `R_SM` / `R_MD` / `GAP_*` / `ICON*` / `GLYPH*` | 不跟主题的档位，**常量** | `gui/src/tokens.rs:413` 起 |
| `icon_sm` / `icon_md` / `icon_box` | 带尺寸的图标包装，禁止裸 `.with_size` | `gui/src/tokens.rs:1003-1020` |
| `edge(t)` / `track(t)` | 两档灰的唯一取值入口（v4 的 `line` / `line-soft`），**不许直写 `t.colors.*`** | 闸 R7 钉着 |
| `xxx_dlg` / `build_*_dlg` | 对话框的构造函数 | `dialogs/*` |
| `is_*` / `has_*` | 纯判断，无副作用 | `is_quiet()`、`has_*` |
| `*_tab` | 一个页签 | `space_tab`、`history_tab`、`readme_tab` |
| `note` / `diag::note` | 写一行日志（见 §4） | `gui/src/diag.rs` |

- **判据类函数（`*_of` / `is_*`）优先抽成纯函数**：「两档『不知道』中性、五档结论不中性」
  这种真值表只有靠纯函数才钉得住，而它治的是**编译器不报、单测不红**的那一类漏
  （有 `_` 兜底臂的 `match` 不会替你穷尽）。
- **一个"档"的名字别把用途写死**：`edge()` 的注释以前写"次按钮描边"，于是分隔线与
  中性状态点以为不归它管、各自直写 token，同一个值长了两个名字。
  起名时说"这是哪一档"，不说"这是给谁用的"。

## 3. 错误处理

- **core 统一用 `Result<T, String>`**，不引入自定义 error 类型、不加 `thiserror` /
  `anyhow`（全仓 32 处 `-> Result<_, String>`，一致到今天没有一个例外）。
  错误串是**给用户看的中文结论 + git 原始 stderr**两句都要（`.stderr` 那一截不能省，
  它是排障唯一的线索）。
- **不 panic**：core 与 gui 的生产路径都不用 `panic!` / `unwrap()` / `expect()` 处理
  **可达的失败**。真到了"不变量被破坏"才用，并且要能说出那条不变量。
- **失败返回 `Err` 而不是折叠成默认值**：把读不出来的配置当默认值存回去，
  用户那一整张仓库列表就静默消失了。**"认不出来"要么报错、要么记账，不要静默取近似**。
- **错误必须走到人眼能看见的一格**：release 是 GUI 子系统、**没有 stderr**，
  所以"出错了但界面上看不见"的地方写 `crate::diag::note(..)`（落
  `%APPDATA%\com.qingbird.git\app.log`，**永不 panic 永不阻塞**）。
  **别写 `eprintln!`**——它在 debug 里好好的，装到用户机器上就凭空消失。
- **`Option` 不许用来假装"可能没有"**：两个分支都返回 `Some` 的 `Option<T>` 是假信号
  （`crates/core/src/repos.rs:1079` 那一处），要么去掉、要么让其中一个分支真的返回 `None`。

## 4. 日志与诊断

- **记"可行动的信息"，不记"每次启动都会发生的事"**：用户拨了字号要记，
  "当前是第几档"不记（他自己在设置页看得见）。
- 一律 `diag::note`，**不弹 `MessageBox`**（一个后台 panic 会变成模态框卡死整条消息泵）。
- 子进程一律加 `CREATE_NO_WINDOW`，**唯一例外是"交付给用户的东西本身就是一个窗口"**
  （`open_terminal`）。判据在 `AGENTS.md`。

## 5. 注释

- **注释写"为什么"，并且要能追到证据**：写"这里是 6，因为 4 + 两条 1px 边框，
  2026-10-08 用户定"，不写"这里用 6"。本项目的教训是**漂的是文档而不是实现**，
  而下次能判出来的唯一依据就是注释里那句"当时为什么"。
- **不留会骗人的话**：查过不生效的调用、已不存在的常量名、`src-tauri` 那种已退役的
  参照物，**连调用带注释一起删**。留一句"看起来还能用"的话比没有注释更坏。
- **标清"现象"还是"缺陷"**：自查清单里只描述现状、却摆在缺陷清单的位置，
  下一个人会拿它当证据去实现一个新功能。
- **`ponytail:` 开头标出有意的简化**，写清天花板和升级路径（这类注释可用
  `/ponytail-debt` 收成台账），**不要给每一处简化都挂一个**。

## 6. 提交信息

照现有的写法，**一行结论 + 为什么**（这一段可以长）：

```
卡间距补上全站证据：27 处全是 6px，而 v4 §3.2 写着 12 —— 漂的是文档不是实现
```

- **说清"改了什么"和"为什么是它"**，不写"修复 bug"、"优化"这种没有信息量的。
- **数字要能被别人复核**（"27 处"、"逐字节相同"），不写"更稳了"。
- 一次提交只做一件事；**文档更正与代码修改分开**（它们是两种证据）。

## 7. 依赖

- **新加一个依赖之前，先答这三个问题**：① 标准库真的没有吗；② 现有依赖里有没有
  已经能用的；③ 这几行自己写是否更短且更可控。**三个都答不出就说明该自己写**。
- 加进 `Cargo.toml` 的依赖**必须当时就有读者**（本项目 core 6 个 / gui 6 个，
  逐个查过都有读者）。不留"以后可能用得上"的依赖。
- 版本唯一出处是仓库根 `Cargo.toml` 的 `[workspace.package].version`，
  子包一律 `version.workspace = true`。

## 8. 出口检查

**四道闸每阶段出口都要跑**（明细与变异验证的纪律在 `README.md` 与 `AGENTS.md`）：

```bash
cargo check --workspace                 # 零错零警
cargo test --workspace --no-run         # 测试模块也要零告警（check 看不到这条）
cargo test --workspace
python scripts/check_design_tokens.py   # 编译器看不见的那一类
```

⚠️ 两条附加判据（都不是"跑绿"能满足的）：
- **单测跑完要核对它没往真实目录写**（本项目抓到过"每跑一次测试就往用户配置里
  塞一条临时仓库"，两周长成 43 条里 40 条垃圾，而所有闸全绿）。
- **新写的判据必须做过变异验证**：弄坏 → 见红 → 逐字节还原 → grep 查残留。
  **只跑绿一次不算**；**变异没红就把"这条断言测不出什么"写进那条测试的注释**，
  不要留一条给"没测"盖章的测试。

## 待补（缺口登记）

- **命名**：D 前缀的测试辅助函数、`#[action]` 命名空间（`qingbird_gui`）这两类还没定，
  现在按就近一致写。
- **`rustfmt` / `clippy`**：仓库里**没有** `rustfmt.toml` / `clippy.toml`，CI 也**不跑**
  fmt / clippy。要不要引入、引入前要不要先跑一次全仓 `cargo fmt`（会产生一个很大的
  一次性 diff）**由用户拍**，定下来之前不写配置文件（写了没有执行者 = 一句假话）。
- **`.editorconfig` / `.gitattributes`**：本机 `core.autocrlf = true` 且无 `.gitattributes`，
  行尾已经引发过多次事故（见 `AGENTS.md` D92 那一条）。**加 `.gitattributes` 会改动
  全部工作树文件的检出形态**，属于需要专门一轮验证的动作，不顺手做。
