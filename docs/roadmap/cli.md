## CLI 工具管理（阶段一：只读扫描展示，2026-10-13）

**结论**：新增 CLI 工具屏（导航轨第 4 个入口 `Nav::CliTools` / 第三种 `Page`），
左栏工具列表 → 右栏只读详情，仿仓库屏骨架。**阶段一只扫 scoop / npm / pipx
这三个输出是 JSON 的包管理器，只读展示**（名称 / 版本 / 来源 / 命令 / 安装目录）；
升级、卸载、数据目录、桌面关联、图标提取、共享缓存清理都归后续阶段。
设计稿在 `docs/NEW/qingbird-git CLI 工具管理模块设计方案-最终版.md`。

**为什么这么落**：
- **业务逻辑放 `crates/core/src/cli/`，不另起 `cli-manager` crate**（设计稿原写独立 crate）。
  它要派生外部命令（`CREATE_NO_WINDOW` 纪律）+ 读那份 SQLite 缓存（"打不开就降级"），
  这两条 core 各有一套——独立 crate 等于把它们复制成第二份，正是本项目为
  "同一属性两个出处"反复交学费的那一类（D73 / D78 同族）。
- **缓存复用同一份库文件**：cli 表加进 `scan_cache::SCHEMA`，打开走 `scan_cache::open_at`
  （建表 + busy_timeout 只有一处）。与仓库缓存同一条约定：加速器不是依赖。
- **命令名从包自己的 `bin` 元数据读，不从包名猜**：本机实测 npm 的 `@larksuite/cli`
  提供的是 `lark-cli`、`@wenyan-md/cli` 提供的是 `wenyan`，包名与命令名经常对不上。
- **provider 的输出格式去上游源码核过、没猜**：`scoop export` 是对象 `{buckets, apps}`
  而不是数组（设计稿按数组写的）；`pipx list --json` 给的才是被 `install-all`
  往返读的那份快照（设计稿写的 `--output json` 是另一种 result envelope）；npm 那条
  拿本机真输出钉死。
- **阶段一不画升级 / 卸载按钮**（v4 铁律：一条点了没反应的键比没有更糟）。

**连带**：
- `Nav` 与 `Page` 各加 `CliTools`。`Page` 上那几处弃式 `match`（`drop_target` 真值表、
  render、状态条中区）当场编译不过 ⇒ 逼着逐处想一遍；`drop_target` 真值表已从两页
  扩到三页。
- **抓帧当场抓出一条**：算侧栏目标宽那句只把"总览页"当成无侧栏、**漏了 CLI 屏**
  ⇒ 进 CLI 屏时仓库侧栏会弹出来。判据改成 `page != Page::Repos`（加第三屏天然跟上）。
- AGENTS 文件地图补 `gui/src/cli_tab.rs` 与 `crates/core/src/cli/`。

**边距一比一 + 顶栏两颗开关 + 底栏跟着屏走 —— 2026-10-13 实机返工（补 v0.4.0，发 v0.4.1）**

用户四条令：① 所有边距与仓库版面**一比一**；② 顶栏左右两颗展开/关闭开关**一比一**；
③ 底栏页脚不能再统计仓库，**要统计 CLI**；④ 右页脚不能再刷新仓库，**要刷新 CLI**。
外加一条他当场拍的：最右那列（预留 AI 助理栏）**要，百分之百的要**。

* **根因不在数值，在出处**：CLI 左栏原来是自己拼的定宽 `div`
  （`.w(px(sidebar_w))` + `side_shell`）。帧上逐像素量：它的白面 **358**、仓库侧栏 **353**
  —— **宽 4px、右移 1px**，而 `cargo check` 零错零警、单测全绿、抓帧看着也只是"差不多"
  ⇒ D73 那一族的又一处（**同一属性两个出处**），只有逐列打色看得见。
* **修法（一个轮子都不新造）**：左栏改挂 `body-split` 的 **0 号面板**，与仓库侧栏同一套——
  宽度来源同一个 `sidebar_w`、同一条 `SIDEBAR_W_RANGE`、朝向气口同一个 `side_shell`
  的 `mr(GAP_TIGHT)`；`cli_list` 只画卡片里的内容。⇒ 几何**天然**相等，
  不是"把 4px 调平"出来的（调平的话那 4px 从哪来没人说得清，下一次还会漂）。
* **判据（帧上逐像素，两屏并排）**：左栏白面 **49..401**、主区卡 **408..1358**、
  AI 助理栏 **1365..1917** —— **两屏三列全部相同**，顶边都是 **y=47**；
  再把左栏收起后同样是 主 **49..998** / 右 **1005..1557**，两屏相同。
* **顶栏两颗开关**：与仓库屏同一颗 `titlebar_toggle`、同一个位置。左 = 收起/展开工具列表
  （`Ctrl B` 走同一个 `toggle_sidebar`），右 = AI 助理栏。
  判据按 **a11y 名字取矩形**（不扫颜色）：CLI 屏上是「**收起工具列表**」client=**(107,17)**
  与「**展开右栏**」client=**(1224,17)**。
  ⚠️ **现场印证了 AGENTS 那条**：第一版按目测点了 (1212,17) —— **画面差 0 像素**（点了个空），
  再点 (1237,17) —— **切到了主题**。两次都不报错，只有"点中了没有"读得出来。
* **底栏左**报「N 个 CLI 工具」（原来是仓库数）；**底栏右**的**文字 / 图标语气 / 点击目标
  三样一起按屏分**，点它调 `scan_cli`。⚠️ 只改点击不改文字会留下"写着「尚未扫描」、
  点下去刷的是另一边"——同一条判据的第二个落点，所以收在一处按屏分。
* **收起态两屏各存一份**：`cli_collapsed` / `sidebar_collapsed`（设计 §10.1「两者互不干扰」），
  **不落盘**（一屏的读法，不是偏好，与 `ov_sort` 同口径）。
* **AI 助理栏接到 CLI 屏**（同一条 `insp-split`），判据收成 `has_inspector()`
  ⇒ 顶栏那颗右开关与"这一屏有没有右栏"同源。⚠️ 这一条**推翻了设计稿 §10.1 那句
  「CLI 屏不占检视栏」**，设计稿已就地加了作废标记。
* **代价如实记**：左栏现在是**可拖宽的面板**（设计稿写的是"定宽即可、先不做拖宽"），
  拖它写的是同一个 `sidebar_w` ⇒ **两屏左栏宽度永远是同一个数**（这是"同档"的字面落法，
  但确实是设计稿没预料到的连带）。
* **连带更正一条旧账**：「抓帧当场抓出一条」那条里写的判据 `page != Page::Repos`
  **已被替换成 `has_left_col()` + `left_collapsed()`**——两屏共用一个面板机制之后，
  "有没有左栏"与"这一屏收没收起"必须分成两个问题问（旧写法只答得了前一个）。
* **AGENTS 一处假话当场修掉**：发版时读产物发现「exe 的 FileVersion」那一项不存在
  （`build.rs` 没有版本资源、属性页一栏都没有）⇒ 已就地更正，并把它与 Q38 的过期状态
  一起收进那一节。
* **设计稿那两行已作废**：`docs/NEW/…-最终版.md` 的「不占检视栏」「定宽即可，先不做
  拖宽/折叠」两处按上面的实情加了日期标记（原句留着，让人看得见被谁在哪天推翻）。
* 出口四闸：`cargo check --workspace` 零警 / `cargo test --workspace --no-run` 零警 /
  core **261** + gui **145** 全绿 / 设计令牌闸干净。
  ⛔ **"装完能跑"仍待他双击定档**；发 v0.4.1 时我能证的只有三条：包是新的（时间戳 + sha）、

**工具图标提取 —— 2026-10-13 阶段二的第一件（补 v0.4.1，发 v0.5.0）**

设计 §10.1 那条三级降里，这一版落的是 **② 从 exe 提图标** 与 **③ 终字符块**；
**① Provider 自报没写**（理由见第三条）。

* ⛔ **设计稿点的那颗 API 实测是错的**（这条比落法本身值钱）。设计 §10.1 写的是
  `SHGetFileInfoW 取 HICON`。实测（本机 9 个 npm 全局包）：npm 的命令全是
  `.cmd` / `.ps1` / 无扩展名的**垫片**，而壳对垫片返回的是**扩展名通用图标**——
  9 个 `.cmd` 取出来的像素**逐字节相同**（同一颗 16×16 的「批处理文件」图标）。
  照它写，屏上会是**九颗一模一样的脚本图标**，比终字符块还差，而
  `cargo check` / 单测 / 抓帧**一个都不会报**。
  改用 `ExtractIconExW`：它返回的是「**这个文件自己带几个图标**」，0 就是没有。
  实测三档：`.cmd` / `.ps1` / 垫片 **0**、`.ico` 文件 **1**、真 PE（`bun.exe` / `deno.exe`）**2**。
* **真数据**：9 个 npm 全局包里**只有 2 个**有自带图标（`bun`、`deno`，落在
  `bin/bun.exe` / `deno.exe`），其余 7 个是垫片 ⇒ 终字符块。
  **这正是设计 §13 预期的那一档**（"大量 CLI exe 本就无图标资源，静默回退"），
  所以界面上"七个块两个图"是**对的样子**，不是没提出来。
* **从哪个文件提**（`exe_candidates`，独立成函数是为了能单测顺序——**没量过顺序的搜索
  就是谁先撞上算谁**）：拿 `install_path` 往下探，**与命令名同名的 exe 排最前**
  （`deno.exe` 赢过随包附带的 `dist/vendor/fastlist.exe`），深度 2、
  跳过 `.git` / `node_modules` / `target`、走满 4000 个目录项就收工（防大包拖住后台）。
* **磁盘缓存**：`<appdir>/icons/<包哈希>-<源哈希>.png`
  （`store::icons_dir()` 是新的那一格，**别在 `cli` 里再拼一遍** `com.qingbird.git`）。
  两个哈希都是**自写的 FNV-1a**——`DefaultHasher` 每个进程换种子，用它算名字等于
  每次启动都换一批名字、**缓存永远不命中**。源哈希里含那颗 exe 的 **mtime + 大小**
  ⇒ 换版自动就是另一个名字。落盘走**临时文件 + 改名**（半张 PNG 的名字已经在了的话，
  界面会一直解出一块空白，而名字命中就不再重提 ⇒ 那台机器上永久空白）；
  写成功后删掉同一个包的旧名字（只删我们自己那套命名）。
* **首屏与后台**：`icon::cached_icons` **一次 `read_dir`** 把磁盘上已有的灌上屏
  （与包清单同一套语言：先渲染、后台再刷），真正的提取在后台**逐颗**跑、
  **提完一颗 notify 一次**；行内先画终字符块、好了换图。⇒ 首屏不等磁盘也不等 GDI。
  ⚠️ 这一条与 `dialogs/clone.rs` 那条是同一族纪律（D73 第三型）：**后台在跑而没人搬，
  界面就是"永远停在准备中"**。
* **判据（core 10 条 + 帧）**：
  * 提取那两条的夹具是**手写的一张 `.ico`**（不是拿系统里某个 exe 当素材——那是把
    测试的前提外包给环境）：32 位那一档验"自带 alpha 原样留住"、24 位那一档验
    "**透明必须从 AND mask 补出来**"（不补这类图标会画成一块黑）；
    另有一条钉"没有图标资源的文件必须返回 None"。
  * **变异三条各自精确红**（M1 不补 mask ⇒ 只红 24 位那条；M2 不跳 `node_modules`
    ⇒ 只红候选顺序那条；M3 键里去掉 mtime ⇒ 只红源键那条），**P0 不动代码全绿**，
    还原后 sha `d03b3ba8808b` 逐字节相同、复跑全绿。
    ⚠️ 脚本第一版自己在**变异之间没还原**（AGENTS 记着的那条），P0 于是跑在 M3 的
    残留上报成"与预期不符"——**修法是每条之前无条件还原**。
  * **帧上**（沙箱 + 见下面那条 `npm_config_prefix`）：`bun` 与 `deno` 两行是真图标
    （bun 的笑脸、deno 的恐龙），其余 7 行是终字符块；`@larksuite/cli` 取到的是
    `cl` 而**不是 `@l`**（scoped 名字取末段）；选中 `bun` 时右栏头部那颗 **24px 是同一张图**。
  * 磁盘上落下来的是 **2 张 32×32**（204 色 / 46 色，不透明像素 856 / 669）——
    32 位图标带 alpha 的实证，不是"文件存在"。
* ⚠️ **它做不出来的两件事照实记**：① 帧那一格是**人眼看的**（`frame.py crop` 裁出来读），
  **没有配机器判据**；② 「先字后图」那一瞬（首屏块 → 图）**没抓到帧**——它时序敏感，
  为它写一条判据等于写一条 flaky 判据（本项目为 flaky 交过学费），所以只登记结构化保证：
  首屏那条路上只有一次 `read_dir`，提取全在后台。
* ⚠️ **两档尺寸**：`tokens::TOOL_ICON`(16) 与 `TOOL_ICON_DETAIL`(24)。前者与 `ICON`
  **同值但不是同一档**（那个是 lucide 描边的视觉重量档，这个是位图/字符块要占的方框）。
  两处**同一张图两个尺寸**（设计 §10.1「同源复用」），不是两张图。
* ⚠️ **一个留给他看帧定的观感**：位图**不裁圆角**（Windows 图标自带形状），
  而终字符块是圆角块 ⇒ 一列里两种形状并排。要不要给位图也上圆角（或反过来把块改方角）
  是版面判断，不在本轮自己拍。
* ⚠️ **没验到的第三档**：scoop / pipx 本机缺席 ⇒ 它们那两档的 exe 定位（`install_path`
  换成 scoop 的 app 目录 / pipx 的 venv）**未在本机跑过**，同一颗 `exe_candidates`，
  但"走对了"只有他机器上装了才有答案。

**数据目录 + 共享缓存 —— 2026-10-13 阶段二第二件（v0.5.0）**

设计 §8 的三级降落到代码：`rules.toml`（规则库，**编进 exe**，数据不是代码）
→ provider 自报（`PackageProvider::cache_dirs`，npm 那一档走 `npm config get cache`）
→ 环境变量推断（`$VAR` + 文档默认值，`%APPDATA%`/`%LOCALAPPDATA%`/`%USERPROFILE%`/`~` 展开）。

* ⛔ **实测逮到两个"按名字猜目录"的反例，这一条决定了规则库怎么写**：
  * `%LOCALAPPDATA%\feishu` 有 **1723 MB**，那是**飞书桌面版**的数据目录；
    `feishu-cli` 这个 npm 包自己的配置在 `~/.feishu-cli`（它源码
    `dist/lib/config.js:4` 写死 `join(homedir(), ".feishu-cli")`）。
    猜错的表现：给 feishu-cli 记 1.7 GB——阶段三一旦当缓存勾上，删的是用户飞书客户端的数据。
  * `~/.kimi-code` 有 **127.8 MB**，看着最像"`@moonshot-ai/kimi-code` 的缓存"，
    拆开是 `bin/`（**工具自己的二进制**）+ `config.toml` + `credentials/` + `sessions/`
    ⇒ 是那颗工具的**安装与数据根**，删了等于删工具。**本轮不给它写规则**（无背书），宁可少报。
  ⇒ 规则库只收两类背书：**工具自己的官方环境变量名**（`DENO_DIR`/`BUN_INSTALL`/`CARGO_HOME`…）
  与**源码里写死的那条路径**；匹配是**全等**（包名末段或命令名），不做前缀/模糊。
* **规则解析收在纯函数里**（`cli::dirs::for_package` / `shared`，依赖"环境 + 哪些目录存在"
  两个入参）：单测在一个**假世界**里跑完整条链路，判据是"给定这个环境解析出哪几条"，
  不是"我这台机器恰好有这几个目录"（把测试前提外包给环境那一族）。
* **体积惰性算**（设计 §4 那个 `Option<u64>`）：解析只出路径，体积由界面那条后台通道一条条填。
  搬运窗口实测：进屏 read 的缓存 + 扫完 fresh + carry-接力，四道闸 282/148 全绿。
* ⛔ **一条我踩的坑：搬运对了但串行，界面 16 秒不出一行数字，看着像"没在搬"**（D73 那一族的**反面**）。
  插桩量到串行版 npm 9.7 万 + pnpm 8.9 万 + cargo 12.4 万文件逐条 await ≈ 16 秒；
  改成**每目标一条后台任务**（`background_executor` 多线程池，并发在 `spawn` 那一刻就发生，
  后面 `await` 只是逐个收结果）⇒ **wall time 落到最慢那一条 ≈ 8 秒，首末相隔 0 秒**
  （同一秒内五条全落）。数字逐字节同值——并发只改何时出，不改结果。
  ⛔ 探针核完当轮撤掉、grep 零残留、还原 sha 逐字节相同。
* **持久化用两张新表**（`cli_package_dirs` / `cli_shared_dirs`）**而不是给 `cli_packages` 加列**：
  `CREATE TABLE IF NOT EXISTS` **不会给已存在的表加列**，老用户库里阶段一那张 `cli_packages`
  没有 `dirs` 列，往它的 CREATE 添一列是**静默失效**（新装没事、老用户读不到也写不进、一句错不报）。
  新表新老两份库都建得出，零迁移——单测 `a_stage_one_database_still_reads` 手搓一份阶段一的老库钉着。
* **判据**：core 解析/搬运/缓存往返共 11 条（规则库解析成不成、两个反例守不守住、
