四个具体症结

1

图标按钮靠 tooltip 认命

打开文件夹终端历史README运行命令定时同步内容待提交——8 个 15px 图标一字排开，鼠标不动就完全不知道是什么。

2

6 种浮层各挂各的按钮

自动同步、同步内容、待提交都锚在头部某个 icon 上，位置随按钮排布漂移；再叠上 stash 确认条、忙碌进度条、分叉恢复卡片，纵向节奏被打断。

3

仓库列表和容量面板抢同一个 tab

「容量」是当前仓库的纵向深入信息，却被塞进全局仓库栏里横向切换，切换成本与心智负担都不对位。

4

状态全是文字 chip

「落后云端 3 个提交 / 待推送 5 个提交」要读两遍；↓3 ↑5 ● 这类徽标又太短、缺语义色，只能靠记忆。

2

三条重排原则

先定规则，再画界面。后面每个控件都能追溯到这三条。

动作分三层，一层一个视觉重量

执行（检测/拉取/推送）占视觉中心，用大控件和实心按钮；
命令（测试/构建/开发/依赖）变成带状态的列表行；
查看（历史/变更/定时/空间/README）全部退出主面板，进右侧检视抽屉与 ⌘K。

状态用图形，不用句子

文字 chip「落后云端 3 个提交」→「同步环中心大字 ↓3」+ 环色。
徽标 ↓3 ↑5 → 列表项右侧 双向微型条，长度即比例。
语义色只表达状态，绝不用于装饰。

就近原则：谁的属性，放谁那里

定时同步是单仓库设置 → 放检视抽屉的「定时」页，不占全局位置。
磁盘占用是单仓库深入信息 → 归检视抽屉，不再抢仓库列表的 tab。
语言构成是单仓库统计 → 从通铺页脚收进工作区统计卡。

3

备选方案 B · 极简双栏

如果觉得主推方案改动太大，这是保守版：不做仪表盘、不做统计卡，只把按钮重新分层。

B 方案长什么样

仓库栏（保留，但拆出状态筛选）+ 主面板（同步环 + 三键 + 折叠的「更多」行）。历史 / 变更 / 空间 / 定时收进一个抽屉，命令变成两行紧凑列表。保留现有页脚语言条。

↓3
拉取 推送 检测
▸ 跑测试 · 构建 · 更多（6 项）

什么时候选 B

· 只想解决「按钮太多」，不想要新图表和总览页
· 想先小步验证用户是否接受新的信息分层，再决定要不要做统计
· 需要在两周内看到成品

B 约为主推方案的 1/3 工作量，只动前端，不新增 Rust command。主推方案里唯一必须动后端的是「近 14 天提交」柱状图。

8

实施路线

按「每阶段独立可用」切分，任何时候停下来界面都是完整的。

  1. 阶段 1 · 换色板与骨架纯前端

    前端重写 theme.css 为灰白 10 级灰阶 + 5 语义色；App.css 引入顺序调整；styles/*.css 全部改用新令牌。组件结构不动，保证这一阶段结束时界面已经好看。

  2. 阶段 2 · 动作分流纯前端

    前端新增 Inspector 抽屉组件（变更 / 历史 / 定时 / 空间 四页签）；头部 8 个 icon-btn 收成 1 个「检视」+ ⌘K；操作区 pill 改命令行；日志区改状态栏 + 抽屉；页脚语言条收进统计卡。这一步解决 80% 的拥挤问题。

  3. 阶段 3 · 图形化控件前端 + 1 个新 command

    前端Rust新增 src/lib/syncRing.ts（环的分段/配色/三态映射，配 .test.mjs）；列表项重设计 + 状态筛选芯片 + 双向条；新增 commit_activity command 供柱状图。同步中进度直接画在环上。

  4. 阶段 4 · 总览与批量前端

    前端导航轨 + 总览 Dashboard（状态分布环 / 待处理列表 / 全库磁盘条）；「待处理」支持一键逐个执行（串行，遵守现有 OP_LOCK 互斥）；⌌K 完整命令面板；快捷键（1/2/3 三键、↑↓ 切仓库、Ctrl K 面板、Ctrl T 终端）。

9

需要你拍板三件事

这三个决定会影响整体观感，越早定越好。

1

放弃「纸墨」国风主题，彻底转灰白？

现在的 theme.css 是宣纸底 + 思源宋体 + 纸纹噪点的「纸墨」语言，与你要求的现代极简灰白是两套设计体系。我的建议是彻底切换——两套风格混用（比如灰白底 + 宋体标题）会显得不伦不类。只保留朱砂印章作为 logo。

建议：彻底切换，保留印章 logo
2

走主推方案 Command Deck，还是备选 B？

主推 = 四区结构 + 同步环 + 统计卡 + 总览页 + 检视抽屉 + ⌘K，4 个阶段。B = 只做动作分流 + 颜色体系，1/3 工作量。我建议主推，但可以按阶段 1 + 2 先交付看看手感，再决定要不要做阶段 3、4。

建议：主推方案，但先只做阶段 1–2
3

命令卡片要不要显示「上次运行结果 + 耗时」？

这是新增能力（现在只写进日志区，不做结构化留存）。好处是一眼看出「测试上次就挂了」，坏处是要在 Rust 侧存一份每个仓库的命令运行记录（写进 config.json）。不做也不影响主结构，只是行内少一个状态标签。

建议：做。落盘一份轻量记录即可，成本很低
