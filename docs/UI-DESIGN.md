## 0\. 界面三条铁律

> **这三条是"界面结构"侧的；视觉契约那四条在 [`docs/UI-DESIGN-v4.md`](./UI-DESIGN-v4.md) §1。**
> 「铁律」只在本文件内编号——跨文档引用一律**带文档名**（`docs/DOCS.md` §2.2）。

1. **能用官方库的一律走官方库。** 组件、菜单、分栏、过渡、折叠、命令面板全部用 `gpui_kit::component::\*` 现成件。官方能做的，禁止自己手搓。官方确实没有的， 在本文第 9 节登记原因后才允许自研。
2. **不许出现裸数字。** 字号 / 圆角 / 间距 / 图标尺寸的档位表**在 [`docs/UI-DESIGN-v4.md`](./UI-DESIGN-v4.md) §3**，本文不复述数值（原来那张表是 2026-10 之前的值，已删）。界面组件这一层的专属约束留在这儿：组件尺寸只用 `Size::Medium` / `Size::Small` / `.small()`，禁写 `Size::Size(px(..))` （自定义 px 档会把字和图标一起放大，整屏视觉失准）。
3. **同一界面不出现重复功能项。** 同一动作在同一屏只留一个入口。分层规则见第 6 节。

## 1\. 整体结构

窗口是 **sidebar workspace**（侧栏工作区）：常驻导航 + 变化的内容区。

```
┌──────────────────────────────────────────────────────────────┐
│ 标题栏 40px：Logo · 应用名 · 窗口控制（官方 TitleBar 自绘）        │
├────┬───────────────┬─────────────────────┬───────────────────┤
│    │  侧栏 240px   │  内容区 flex_1      │  检视抽屉 320px    │
│ 导 │  可折叠       │  仓库头（常驻）      │  日志（默认页签）   │
│ 航 │  可拖宽       │  ┌────────────────┐  │  变更              │
│ 轨 │  树形分组     │  │概览│说明│历史│  │  历史              │
│ 44 │  + 右键菜单   │  │    │    │    │  │  空间              │
│    │               │  └────────────────┘  │                   │
│    │ ＋ 添加仓库    │  概览：同步卡 → 命令卡 │                   │
│    │ ⤓ 克隆仓库…   │                     │                   │
├────┴───────────────┴─────────────────────┴───────────────────┤
│ 状态条 28px：仓库数 · 上次扫描时间 · 当前选中路径              │
└──────────────────────────────────────────────────────────────┘
```

**四个列区**：导航轨（我在看哪一屏）→ 侧栏（有哪些仓库）→ 内容区（这个仓库怎么干）
→ 检视抽屉（刚才发生了什么）。抽屉可收起，收起后内容区获得空间。

**三个导航按钮，顺序固定**（用户拍板）：

| 位置 | 按钮 | 行为 |
|---|---|---|
| 第 1 个 | 总览 | 切到总览页，**侧栏收起**，右侧铺满全量统计 |
| 第 2 个 | 我的仓库 | 侧栏展开并滚动定位到「我的仓库」分组，展开该组 |
| 第 3 个 | 第三方仓库 | 侧栏展开并滚动定位到「第三方仓库」分组，展开该组 |

第 2、3 个按钮**不切换页面**，只驱动侧栏：展开侧栏 → 展开对应分组 → 定位滚动。 这比"切页"更省心：用户想在两组之间对照时不必来回切屏。

**一个例外分支**：若当前停在总览页，点第 2/3 个按钮要**同时**切到仓库页
并选中该组第一个仓库 —— 否则用户点了按钮，内容区纹丝不动，行为不可预期。
已经在仓库页时，只驱动侧栏，不动内容区（对照场景）。

所以 `Page` 只需两态（`Overview` / `Repo`），"当前看哪一组"是**侧栏的焦点态**，
不是页面态 —— 这是"第 2、3 个按钮不切页"能成立的前提，**别把它做成第三个 Page 变体**。

**进总览时侧栏收起**（用户拍板）：总览的内容是四张状态卡 + 活跃度图 + 汇总表，
横向要宽度；侧栏在这个屏上没有任何可操作对象，留着只是占 240px。 收起走
`resizable` 面板的宽度过渡（见 2.1 / 2.6），**不硬跳**。
从总览点任意仓库行 → 自动展开侧栏并定位到该行（否则用户点完看不到自己点的是谁）。

**"这屏没有侧栏"与"用户折了侧栏"是两个值**：进总览只切屏，不改 `sidebar_collapsed`。
混成一个值的话，用户回仓库页会发现刚摆好的侧栏不见了。

**启动首屏**：默认停在「总览」，侧栏收起，「我的仓库」组默认展开（下次进侧栏时是展开的）。

### 区域尺寸

| 区域 | 尺寸 | 约束 |
|---|---|---|
| 标题栏 | 三档 36 / 40 / 44px（随缩放档，`tokens.rs::metrics()`） | 固定高，不参与压缩 |
| 导航轨 | 40px + 1px 分界 = 41px | 常驻列，任何时候都在 |
| 侧栏 | 默认 240px | 范围 200–360px，可拖宽，宽度持久化 |
| 内容区 | 剩余 | flex_1() + min_w_0() + min_h_0() |
| 检视抽屉 | 320px | 仅仓库详情页；可收起，收起后不占宽度 |
| 状态条 | 三档 26 / 28 / 32px（`fs_sec() × 2`） | 固定高 |
| 窗口下限 | 1080×640 | 见下方预算验算 |

**2026-10-14 实机帧核对**（1296×828，small 档）：标题栏 36、轨 41、状态条 26、
CLI 左栏 250（用户拖宽后）——上表原来写死的 48/56/28 是旧值，已按
`tokens.rs` 三档修正；CLI 屏全框几何另见 §3.11.2。

标题栏与状态条**用官方 `TitleBar` / `StatusBar`**，尺寸按上表给，不自己拼窗口控件
（窗口控件、拖拽区、双击缩放都是官方件里现成处理过的）。窗口选项要以
`TitleBar::window_options()` 为底，否则窗口没有能拖的地方。

宽度预算（1080px 下最窄状态）：抽屉收起时 1080 − 轨 41 − 侧栏 200 = 839px 主区；
抽屉展开时（320px）主区剩 519px，仍可工作。 **要加列之前先按这两个式子重算**，别凭感觉调。

### 1.1 检视抽屉

右侧抽屉**只在仓库详情页出现**，总览页不显示（总览没有"当前仓库"这个对象）。

**它是版面里的一列，不是浮层**：不用官方 `Sheet`——`Sheet` 是模态件，带遮罩、
吃掉整窗点击、劫持 Esc 与焦点，与"收起后内容区获得空间"直接冲突。
`Sheet` 留给提交 diff（那种才真需要盖住界面）。

页签：**日志（默认）/ 变更 / 历史 / 空间**。 日志排第一是因为"刚才跑的东西
结果怎样"是最高频的查看需求。抽屉收起不会丢失日志状态——它只是不可见，
日志按仓库各自保存（见 3.4.1）。

## 2\. 侧栏

### 2.1 侧栏的壳：宽度与折叠归 resizable，仓库行归 3.1 的树

侧栏分两半，各用各的官方件，别混：

| 部分 | 用什么 | 为什么 |
|---|---|---|
| 宽度 / 拖拽 / 折叠 | `h_resizable` + `resizable_panel` + `base::transition` | 见 2.6 |
| 仓库树 | 阶段 4 起用 `component::sidebar::{Sidebar, SidebarMenu, SidebarMenuItem}` | 状态点 / 徽标 / 右键菜单都在 `SidebarMenuItem` 上 |

**为什么折叠不用 `SidebarCollapsible::Offcanvas`**（与路线表 D12 同一结论）：

1. 官方 `Sidebar` 的折叠走自己的 `EffectTransition`，**全程没有 `cx.reduce_motion()` 判断**
   （`component/src/sidebar/mod.rs`），而 4.3 节要求尊重系统减弱动效。
2. `ResizablePanel` 的 `min_w` 由 `size_range` 硬夹。侧栏在 `resizable_panel` 里时，
   滑到 0 会被下限按回 200px —— 除非把 `size_range` 放开到 0，而那样拖宽就再也夹不住下限。
3. 官方 `Sidebar` 的内容区只收 `SidebarItem`（菜单式列表）。仓库树那套
   「状态点 + 名称 + 徽标 + 悬停」不是那个形状，硬塞要写一层把 `Shell` 状态快照进
   `SidebarItem` 的胶水；阶段 4 一旦把仓库行换成 `SidebarMenuItem`，这层就白写。

所以阶段 3 的落地是：

```rust
// 宽度只有一处真源：ResizableState 里第 0 号面板的宽度。
// 折叠 / 展开 / 切总览都只是改"目标宽度"，中间值由官方 transition 补出来
let target_w = if self.sidebar_collapsed || self.page == Page::Overview {
    px(0.0)
} else {
    px(self.sidebar_w)
};
let anim_w: Pixels = transition("sidebar-width", target_w, policy, window, cx);
let animating = (anim_w - target_w).abs() > px(0.5);
// 补间中或目标为 0 时下限放开，否则 min_w 把面板按回 200px，凭空多一条空槽
let min_w = if animating || target_w <= px(0.5) { px(0.0) } else { px(SIDEBAR_MIN_W) };
```

折叠状态由 `SidebarToggleButton` 控制，放在**标题栏**而不是侧栏内部
（放进侧栏的话折叠后按钮自己会消失，没法再展开回来）。也没放内容区左上角——
内容区归三屏各自的头部管，插进去要么三处各插一遍，要么给所有页面让出一条常驻行；
标题栏本来就是窗口级开关的位置，折叠后它照样在。


### 2.2 树结构

两组固定，顺序固定：**我的仓库 → 第三方仓库**。

```
▾ 我的仓库      (GitBranch)  12
  ✓ qingbird-git
  ● other-project
  ⇩ lag-behind            可更新
▸ 第三方仓库    (Users)      5
```

* 分组标题 = `SidebarMenuItem::new("我的仓库 · 12")` `.icon(GitBranch)`
  `.suffix(旋转的 ChevronRight)`，**不带子项**
* 仓库行 = `SidebarMenuItem::new(name)`，同样不带子项
* **分组标题不承担选中语义**：它只管展开/收起；选中永远发生在仓库行上。用 `.active(true)` 标记当前选中的仓库行。
* **开合态存在 `Shell.group_open`，不交给 `SidebarMenuItem` 的子菜单**（D13 出入 2）：
  子菜单的展开态藏在官方组件内部的 `window.use_keyed_state` 里，外部拿不到，
  而导航第 2/3 个按钮与总览点行**必须能从外面把某一组打开**。
* **行要平铺在滚动容器里，不套 `SidebarMenu`**。那层只是个 `v_flex`，但它会把行
  藏进子容器——滚动容器的直接子元素变成两个菜单，定位滚动换算不出行号就废了。

### 2.3 仓库行内容

一行只放三样东西，固定三列，正好对上 `SidebarMenuItem` 的三个槽位：

| 位置 | 槽位 | 内容 |
|---|---|---|
| 左 | `.icon()` | 状态**字形**（按档位，14px），取色走 `dot_color(bucket)` |
| 中 | `.label()` | 仓库名（省略号截断） |
| 右 | `.suffix()` | 徽标：待推送 N / 未提交 N / 可更新 / 已分叉，空则不画 |

状态字形与徽标的取色口径**必须**来自既有的 `bucket_of()`，这是全站唯一分档口径
（侧栏、总览、同步环、⌘K 状态点都从这里取），不要另写一套判定。

| 状态 | 字形 | 语义 |
|---|---|---|
| 已同步 | `Check` | 无需处理 |
| 有未提交 | `CircleDot` | 有活没提交 |
| 有本地提交 | `ArrowUp` | 可推送 |
| 落后 | `ArrowDown` | 云端有更新 |
| 已分叉 | `GitMerge` | 需人工处理 |
| 未扫到 | `Circle` | 状态未知 |

> ⚠️ **用字形不用纯色圆点**（D13）：`SidebarMenuItem` 没有纯装饰左槽；
> 4px 圆点在 240px 侧栏里几乎看不见；更要紧的是五档全靠色相区分的话，
> 色觉障碍下"落后"和"已分叉"会长得一模一样。字形把冗余编码进形状，不额外占宽度。
>
> ⚠️ **下面这张色表与代码不一致（Q7，未拍板）**。这张表与第 4 节其实一致，
> 不一致的是 `state.rs::dot_color`——以及旧 React 版（fork 用的是**紫** `#7c3aed`，
> 注释写"危险但非错误"，但 `theme.json` 里根本没有紫色档）。
> 代码现状：synced 绿 / dirty 蓝 / ahead 蓝 / behind 橙 / **fork 也橙**。
> 另有一点：这张表把"已同步"定成蓝色，但已同步是**占比最高且无需动手**的一档，
> 满屏蓝反而像都在报错。**建议以旧 React 版三档为基线，fork 改 `danger` 红**——
> 三套说法的完整对照见 `docs/UI-ROADMAP.md` 的「Q7 长说明」。拍板前代码保持现状。

| 状态 | 语义 | 取色 |
|---|---|---|
| 已同步 | 无需处理 | chart.1 蓝 |
| 落后 | 云端有更新 | chart.3 橙 |
| 有本地提交 | 可推送 | chart.2 绿 |
| 已分叉 | 需人工处理 | chart.4 红 |

未提交数是独立维度，与上面几档可重叠，不参与状态取色。

### 2.4 右键菜单

仓库行挂 `SidebarMenuItem::context_menu`（官方件，自带键盘导航与关闭语义）。 **不要自己拼浮层**。

> `PopupMenu::new` 是 `pub(crate)`，外部自建不了——只能用 `context_menu(f)` 传进来的
> 那个实例，加项用 `PopupMenu::item(impl Into<PopupMenuItem>)`。
> `PopupMenuItem` 有 `new` / `icon` / `disabled` / `checked` / `on_click` / `separator` / `link`，
> **没有 `danger()`**——危险色要自己写进图标或文案。

**我的仓库**的菜单：

| 菜单项 | 行为 |
|---|---|
| 打开 | 选中并进详情页 |
| 提交并推送… | 打开提交对话框（见 3.7） |
| 移到第三方仓库 | 改 is_third_party，直接生效 + 通知 |
| 打开文件夹 | 调系统文件管理器 |
| 在终端中打开 | `cd` 到路径并起终端 |
| 复制远程地址 | 复制 clone URL |
| 重命名… | 改本地显示名（不改仓库名与磁盘文件） |
| 编辑… | 打开编辑对话框（命令、归属、定时） |
| 移除 | 从列表移除（可逆 → 走通知撤销，不弹确认框） |

**第三方仓库**的菜单：

| 菜单项 | 行为 |
|---|---|
| 打开 | 选中并进详情页 |
| 移回我的仓库 | 改 is_third_party，直接生效 + 通知 |
| 打开文件夹 | 调系统文件管理器 |
| 在终端中打开 | `cd` 到路径并起终端 |
| 复制远程地址 | 复制 clone URL |
| 在云端打开 | 浏览器打开 `browse_url_from_remote(remote_url)` |
| 重命名… | 同上 |
| 编辑… | 打开编辑对话框 |
| 移除 | 同上 |

**「提交并推送…」只出现在我的仓库**，第三方出现即为越界。阶段 4 之前它与
「克隆仓库」一样**明确置灰**并带 tooltip 说明——给一个点了没反应又没解释的入口
比不给更糟，"还没接线"要说在脸上。

**归属变更直接生效**（用户拍板）：归属只是分组标签且完全可逆，不弹确认框。 执行后发一条 `window.push_notification(..)`：「已移到第三方仓库」，带"撤销"动作。

> `Notification::action` 的闭包签名是
> `Fn(&mut Self, &mut Window, &mut Context<Self>) -> Button`——**必须返回一个 `Button`**，
> 点击逻辑自己挂 `.on_click`。外层是 `Fn` 不是 `FnOnce`，闭包里要用外面的数据得先 clone。

**移除的撤销要写回整条记录**：撤销走 `repos::add_repo` + `restore_entry`。
只用 `add_repo` 的话，它造出来的是一条最小记录，等于把用户攒了几个月的别名、
自定义命令、定时设置全清空。

菜单项的动词、图标、启用态、结果在右键菜单、详情页、⌘K 三处必须**完全一致**。

### 2.5 侧栏底部两个动作

树下面是分隔线，再下面两个并排的 `default` 按钮（**不放导航轨**——导航轨只回答
"我在看哪一屏"，见 6 节）：

| 按钮 | 行为 |
|---|---|
| ＋ 添加仓库 | 选本地已有目录（`repos::add_repo`） |
| ⤓ 克隆仓库… | 填远端地址克隆（见 3.10） |

**不合并成一个带开关的对话框**：两种输入类型、两种心智模型，合并会让两边都难用。

侧栏**头部**另有标题「仓库」+ 仓库计数 + 筛选开关。筛选框默认收起（D8），
点开是官方 `Input::small()` + `cleanable(true)`，**另起一行**——
塞进标题行会被 40px 的固定行高横向挤扁。

> `InputState` 公开 API 极少：`value(&self, cx)`、`focus_handle`（需 `Focusable` 在 scope），
> **没有 `set_value` / `reset` / `focus`**。清空靠 `cleanable`，
> 聚焦靠 `name_input.read(cx).focus_handle(cx)` + `window.focus(&fh, cx)`。

### 2.5.1 定位：四条路径一个入口

侧栏行点击、右键菜单「打开」、总览表格点行、⌘K 切仓库——**全部走
`Shell::reveal_repo(path, cx)`**，不要各写一份。它做五件事：

1. 切到仓库页（`Page::Repos`）
2. 展开侧栏（`sidebar_collapsed = false`）
3. **只展开目标那一组**（另一组是用户自己折的，为了跳一个仓库把他摆好的侧栏也撑开，
   等于每次跳转都在改他的桌面）
4. `side_focus` 跟着走到那一组
5. 记 `reveal = Some(path)`，下一帧 `apply_reveal` 用 `ScrollHandle::scroll_to_top_of_item` 滚过去

导航第 2/3 个按钮同理，但多一条：**已经在这一组里就只切焦点、不动选中**，
否则点两下会莫名换掉当前仓库。

> 行号换算靠「索引 = 渲染顺序」这条约定：`sidebar.rs` 写 `ix`，`actions.rs::apply_reveal`
> 用同一套算法反算。**两边必须一起改**。行被过滤掉了就别定位——硬滚到一个看不见的行没有意义。
>
> `scroll_to_top_of_item` 在容器尚未布局时会把请求**留在 handle 里逐帧重试**
> （`scroll_to_active_item` 的 `None => Some(active_item)` 分支），所以在 `render`
> 开头发起定位是安全的，不用等布局完成。


### 2.6 折叠 / 拖宽 / 动效

这是本次的硬需求，全走官方件，不手搓：

| 需求 | 官方件 | 接法 |
|---|---|---|
| 拖宽拉窄 | `h_resizable` + `resizable_panel` | 见下方代码 |
| 折叠展开 | 同上：把第 0 格的宽度动到 0，到 0 就摘掉面板 | 见 2.1 |
| 过渡动画 | `gpui_kit::base::transition` | 见下方代码 |
| 减弱动效 | `transition` 内部读 `cx.reduce_motion()` | 见下方代码 |

**拖宽**：内容区外层用 `h_resizable` 分成「侧栏 / 主区」两格。

```rust
h_resizable("body-split")
    .with_state(&self.split)                 // 持久化 Entity<ResizableState>
    .child(
        resizable_panel()
            .size_range(px(200.)..px(360.))  // 拖宽范围的硬约束
            .size(px(self.sidebar_w))        // 定宽面板要 flex_none()，否则会被 flex_grow 挤走
            .flex_none()
            .child(sidebar_element),
    )
    .child(resizable_panel().child(main))    // 主区不写 size，让它吃掉剩下的全部宽度
    .on_resize(|state, _, cx| { /* 松手时读 sizes()[0] 落盘 */ })
```

**折叠不占位**靠"宽度到 0 就把面板整个摘掉"，不靠 `Offcanvas`：

* 面板的挂/摘由 `ResizablePanelGroup` 按子元素个数自动同步（`sync_panels_count`），
  显式再调 `remove_panel` / `insert_panel` 反而会和它打架。
* 补间期间 `size_range` 的**下限要放开到 0**，否则 `min_w` 会把动画按死在 200px。
  平时不放开，拖宽才夹得住 200–360。
* 面板刚挂上那一帧用 `insert_panel(Some(anim_w), Some(0), cx)` 而不是 `resize_panel`：
  状态里还没有第 0 号面板时 `resize_panel` 是空操作，面板会退回 `initial_size`（全宽）
  闪一下再缩回去。
* **非补间时不要写宽度**：那时宽度归拖拽，每帧写会把用户刚拖出来的宽度一帧拽回去。

`ResizableState::sizes()` 可读回各格实际尺寸，比自己记一份宽度可靠
（官方注释明确说它能反映"用户拖过之后"的状态）。

**过渡动画**：宽度走官方 `transition`，值从动效 token 取，**不自己算时长**。

```rust
use gpui_kit::base::motion::{Transition, transition};

let motion = cx.theme().motion_tokens();
let policy = Transition::new(motion.duration_fast).easing(motion.easing_move.clone());
let w: gpui_kit::Pixels = transition("sidebar-width", target_w, policy, window, cx);
```

`transition<T>(id, target, policy, window, cx)` 的第一个参数是 `impl Into<TransitionId>`，
**必须是稳定字符串**（同一处复用同一个），否则每帧新建过渡会一直重启动画。
库内 `component/src/resizable.rs` 的注释专门讲了这个坑：过渡只在运动中请求帧，
静止时零开销，所以要无条件采样，不要只在动的时候调。

**减弱动效**：不需要应用侧自己判。`base/src/motion.rs` 的 `transition_with_status` 开头就是
`if cx.reduce_motion() || policy.duration.is_zero()`，为真时直接把 `from` 与 `target`
都写成终值并返回 `Finished`。**应用侧另写一份 `if cx.reduce_motion()` 只会和它重复**，
而且容易漏掉"重置 from"那半句——那半句正是让下一次反向动画不鬼畜的关键。

**落盘**：宽度与折叠态写进 `Settings.sidebar_w` / `Settings.sidebar_collapsed`，
与 Tauri 版共用同一份 `config.json`。宽度夹范围在 core 的 `clamp_sidebar_w` 里做一次，
界面不再自己夹第二遍。

> ⚠️ `sidebar_w` 不能用裸 `#[serde(default)]`：那取的是 `f32::default()`（0.0）而不是
> `Settings::default()`（240.0）。必须 `#[serde(default = "default_sidebar_w")]`。

## 3\. 内容区三页

### 3.1 总览页（首屏）

总览常驻一页。**只统计，不操作**——这里是"看一眼全局"， 批量动作是另一回事（见 6.2）。

结构自上而下：

1. **页头**：标题「总览」+ 副行「N 个仓库 · 我的 X · 第三方 Y」。
2. **四张状态卡**：已同步 / 落后云端 / 有本地提交 / 已分叉。 数字用 `FS_NUM`，颜色取 `bucket_of` 口径，**卡片不加边框阴影**， 只靠背景（`secondary.background`）与间距分组。
3. **提交活跃度波形图**：近 14 天，官方 `chart::AreaChart`（2026-10-03 实机三轮由 `BarChart` 改来，见下面的注）。 日期键必须用本地时区，不能用 `toISOString`（会串日）。
4. **仓库汇总表**：官方 `table::{DataTable, TableState}`，列为 名称 / 归属 / 分支 / 状态 / 落后 / 待推送 / 未提交。 点击行 = 选中该仓库并进详情页。 **七列宽度跟随窗口缩放**（见下面的注）。

> 用 **`DataTable` + `TableState`**（带状态的官方件）而不是纯展示的 `table::Table`：
> 后者没有排序、没有行选中事件，就没法接"点行跳仓库"。
> 行的点击从 `TableEvent::SelectRow` 订阅拿到，**不要**自己在 `render_td` 里塞
> `on_click`——单元格拿不到"整行"的语义，塞进去点哪儿都跳。

表格首列的复选框（批量选择）**不在总览页**——那是批量功能，不是总览功能， 放这里会让"看统计"和"选一批干活"混在一起。同理底部的批量条整体移除。

**「状态」列的文案密度比侧栏低**：表格里写「待推送」「落后」，不带数字，
因为旁边就有独立的数字列；侧栏那一格只有 200px，必须带数字（"待推送 3"）。
但"落在哪一档、什么颜色"只有一份实现（`sidebar::badge_tone`），两边都调它。
数字 0 显示成 `—` 而不是 `0`：「落后 0」和「没落后」在用户眼里不是一回事——
前者是"确认过没有"，后者是"还不知道"。

**活跃度是进总览页才扫的**，不是每次进总览都重扫。每个仓库一条 `git log`，
仓库多了不便宜，而用户多半只是路过看一眼。切走不扫，回来时用已缓存的。
后端 `commit_activity_all` 只合并各仓库「有提交的日子」，**补齐 14 天空白是界面自己的活**
（`overview::fill_days`）——x 轴上少一天会让后面的点往前挤，少一天两根就靠拢了，
看起来像"提交变频繁了"。宁可画一个 0，也不能让那一天消失。

> **口径修正（2026-10-03 实机二轮，D47）**：本节原写「不是启动就扫」，
> 与 1.0 节的「启动首屏：默认停在总览」合起来的结果是**首屏柱状图永远是一排 0 高度**，
> 读起来像"近两周没人提交"。现在的口径是
> **「本会话第一次显示总览页时扫一次，之后来回切不重扫」**——
> 首屏就是总览，那一次就是启动那一次。落法是 `Shell::ov_need_scan` 一次性标记，
> 点导航轨回来的那条路仍走 `go` 里的扫描，两条路不重复扫。

> **柱顶标签写什么（D43）**：`BarChart::label` 是**每根柱自己的值**，
> 不是轴标签。写日期等于把 x 轴的信息再抄一遍、抄 14 遍（早先就是这么，
> 14 根柱顶全印着同一个 `2026/09`）。它写 `count`；日期归 `band()`，
> x 轴只留 `M/D`，完整日期在 tooltip 标题上。
>
> ⚠️ 派生一条：`YYYY-MM-DD` → `M/D` 那个函数早先按 `split('-')` 的**前两段**取，
> 拿到的是「年-月」。**两套段数不同的格式不能用「按位置取」来兼容**，
> 要按语义取（跳掉年段）并对缺段容错。

> **`DataTable` 的列对齐（D44）**：基座的 `Column::text_right()` 只有
> `table::Table` 那条路会读（`table::TableCell` / `TableHead` 里的
> `when(align == Right, justify_end)`），总览用的 `DataTable` + `TableState`
> **全程没有读过 `align` 字段**——写了不报错、不 panic、也不生效。
> `p_0()` 反倒是生效的（`state.rs` 读了 `column.paddings`），
> 所以只去掉内边距的真实观感是「状态 pill 尾巴紧贴下一列的数字」。
> 现在三个数字列统一**左对齐 + 默认内边距**，表头与数字同一起跑线。
> 真要右对齐得在 `cell()` 里自己摆 `justify_end`，而那样表头仍是左对齐的，两边反而错位。

> **柱状图 → 波形图（D54，2026-10-03 实机三轮）**：改用官方 `AreaChart`
> （折线 + 底下填充）。三点要注意：
> ① **曲线不用显式 `.natural()`** —— `Curve` 的 `#[default]` 就是 `Natural`，
>    写出来只是把默认值再说一遍；
> ② **填充不能是实心 accent** —— 整块实心色会把网格线吃掉、曲线反而读不出来，
>    压到 `opacity(0.12)` 才只当"底"；
> ③ **`AreaChart` 没有 `BarChart` 那套 `band / label / corner_radii`**，
>    **柱顶标签是随组件一起没有的**。日期信息仍由 x 轴 `M/D` + tooltip 标题承担
>    （这两处的分工与 D43 定的完全一致）。
>
> **详情页那个单仓库迷你图保持柱状图**：那是另一个尺度、另一个场合（详情页窄栏），
> 换成面积图反而看不清。同一屏里两种图各自合适，比"全应用统一一种图"更要紧。

> **七列宽度跟随窗口缩放（D55，2026-10-03 实机三轮）**：纯函数
> `ov_column_widths(avail)`，三步——① 按 `avail / 736` **等比**缩放；
> ② 倍数夹到 `1.6`、每列抬到各自下限；③ **余量按「仓库名 : 分支」的基准比例
> 补给这两列**，保证合计铺满。
>
> 为什么必须有第 3 步：合计少一点，卡片右边空一条；多一点则冒出横向滚动条，
> 表格会左右晃。**合计只会偏宽不会偏窄**——偏宽有滚动条告诉用户"还有"，
> 偏窄则是右边一条说不清缘由的空。窄到下限顶住时停在下限上，宁可出滚动条
> 也不要表头断字。
>
> 为什么要有第 2 步：3369px 的内容区 ÷ 736 = **4.6 倍**，「归属」那列会变成
> 385px 宽的一片空白，比不改还难看。超出的余量给「仓库名 / 分支」——
> 那两列本来就是会随窗口变长的文本列。
>
> **⚠️ 这条已被 D56 推翻**：原写「量的是表格上一帧实测的可用宽度」，
> 理由是「只有表格自己知道自己有多宽」——**而那个宽度正是被列宽决定的**，
> 拿被输出决定的量当输入构成正反馈环，鼠标一动界面就持续右拉直到出窗。
> 现行口径：`avail = 窗口宽 − OV_TABLE_CHROME`，**开环**。
> 那圈固定开销（轨 + 分隔线 + 页面内边距 + 卡片描边 + 纵向滚动条）宁可多扣：
> 少扣会出横向滚动条（回到环的起点），多扣只是右边空十几像素。

### 3.2 我的仓库详情

**这是主工作区**，要能直接干活。

**仓库头**（常驻，不随页签切换，**两类仓库共用同一个**）：

```
qingbird-git  [我的]  ⑂main                       📁  ⌨  🌐  📋
F:\AIwork\qingbird-git                    最后提交 2 小时前
┌────────────────────────────────────────────────────────┐
│ https://github.com/…/qingbird-git.git                  │  ← 只读地址条
└────────────────────────────────────────────────────────┘
```

右侧四个图标按钮：打开文件夹 / 开终端 / 云端主页 / 复制地址（见 3.8）。
第二个 `⌨` 走 `Ctrl T`，第一个 `📁` 与后两个的关系见 3.8 的说明。

**为什么两类仓库必须共用一个头**：头承载的是"我在哪个仓库、它有多旧、我能跳到哪去"，
这几件事对"我的"和"第三方"没有区别。分成两个头，就会有两处各自漂移的按钮顺序、
两套路径显示格式、两份该用同一份 `bucket_of` 的取色——而用户在两个页面之间来回切时，
那种"看着一样、点下去不一样"的差异最伤信任。差异只落在两处：页签序列与概览页内容。

**「云端主页」的门槛是 `has_upstream`**（而且 `browse_url_from_remote` 要能得出网址），
**不是按归属分**。早期版本把它做成"第三方专属"，结果仓库头是两类共用的、
右键菜单却一边有一边没有——这个不一致直接暴露在界面上。

> **只读地址条是官方 `Input` + `.readonly(true)`**（阶段 7 一度是手写的，阶段 8 换回来了）。
> 换回来的理由：`InputState` **有** `set_value(value, window, cx)`——
> `component::input::InputState` 是 `gpui_base::input::InputState` 的再导出，
> 方法定义在 `base/src/input/base/state.rs`。当初只看了 `component/src/input/state.rs`
> 里那个 `AnyInputState` 门面（它确实只有 `value` / `focus_handle` / 构造时的 `placeholder`），
> 没往下一层找，于是误判成"装不进静态值"。
> 官方件白拿的是：可选中复制、焦点环、readonly 的灰字重、选中时不高亮背景。
> **全应用只建这一个 `Entity`**，切仓库时 `set_value` 换内容——每仓重建一个的话，
> 旧 Entity 还挂在上一帧的渲染里，焦点与选区会错位。也不在 `render` 里塞：
> `set_value` 会把光标放到末尾并把视图滚回开头，每帧改一次会清掉用户的选区。
> 地址条上**没有**复制图标——仓库头第四个按钮就是"复制远程地址"，
> 同一串地址摆两个复制入口是多余的。

**页签**（官方 `TabBar`）：

| 页签 | 内容 | 归属 |
|---|---|---|
| **概览**（默认） | 同步卡 + 分叉条 + 命令卡 + 磁盘摘要 | 两者都有（内容按归属裁剪） |
| **说明** | README（`TextView::markdown`） | 两者都有 |
| **历史** | 最近提交列表 → 点行进 Sheet | 两者都有 |
| **空间** | 磁盘占用 / 大文件 / 缓存清理 / .gitignore 建议 | 仅我的仓库 |
| **同步设置** | 定时自动同步 / 检测到更新后自动拉取 | 仅我的仓库 |

**页签下标是全局的，不跟仓库走**——切页签不是切仓库，多仓库用户不该每换一个
都要点回「概览」。但切仓库时会把下标**夹回范围**：从第三方（3 个页签）切到我的
（5 个）时，下标可能还停在被裁掉的位置上。

「概览」页内的区块顺序：

1. **同步卡**（执行层，视觉最重）：左边同步环，右边状态句 + **三键**，最下面一行
   「提交并推送…」。三键顺序固定为 **拉取 · 推送 · 检测**——快捷键 `1·2·3`
   按**屏幕位置**对位（用户是先看见按钮再按位置的键），顺序一改快捷键就名不副实。
   落后时「拉取」转 `primary`、待推送时「推送」转 `primary`、分叉时两把都转
   （得先变基或拉取，推送也会被拒）。「检测」永远 `ghost`：它是三键里唯一
   不改动本地的一把，放末尾不会让人误以为它也在写。
   **第三方那一格留一个同宽的占位**，让「拉取」永远在第一个位置。
   同步环是官方 `ProgressCircle`：弧长 = 落后 + 待推送（10 个提交画满一圈），
   颜色 = `bucket_of` 的那一档，中心放大数字 + 状态词。
2. **分叉提示条**：仅当 `ahead>0 && behind>0` 时出现，
   提供「备份并变基到云端」「撤销变基」「只看差异」。
3. **提交并推送…**：在同步卡**下方一行**，不进三键行（理由见 3.7）。
4. **命令卡**：四条命令行（测试 / 构建 / 开发 / 安装依赖）+ 钉住的自定义命令（上限 3）。
   每行**一个主操作 + 一个溢出菜单**。主操作区与「⋯」是**两块**而不是一整行加一个
   按钮——合成一块就得靠 `stop_propagation()` 拦点击，而弹层触发器的命中区与整行
   重叠，拦掉的时机不可控。溢出菜单走官方 `DropdownMenu`（内部就是 `PopupMenu` +
   `Popover`）：复制命令 / 编辑命令… / 清除命令（钉住行是「取消钉住」）。
   卡片头的「编辑」开同一个对话框。
5. **底排两张卡**：
   - **磁盘摘要卡**：只给一行「占用 1.6 GB · 可清理 820 MB」+ 一个「查看」按钮，
     **完整空间面板在「空间」页签里**（避免概览页过长）。「查看」按枚举切页签，
     不写死下标——第三方仓库的页签序列是裁剪过的。
   - **未提交变更卡**（300px 固定宽）：未提交文件数 + 已暂存 / 未暂存 / 未跟踪的拆分
     + 最后提交时间 + 一个「查看变更」（跳检视抽屉的变更页签）。
     **它不再放拉取 / 推送**——那两把键归同步卡，同一动作在一屏里出现两次，
     两处都会各自改状态机，迟早对不上。

**这五块按内容高度排，整页可滚；底排两张卡顶对齐。**（2026-10-03 实机二轮修正，D42）

三条都是被实机逼出来的，早先写法各自"看起来合理"：

* **不给任何一块 `flex_1` 吃剩余高度。** 命令卡只有 4 行时会在卡内留两百多像素空，
  读起来像内容没加载出来；给了就等于用"填充"掩盖"这一屏本来就那么高"。
* **整页要能滚。** 五块加起来约 716px，而窗口下限 1080×640 时可用高度约 414px
  （1.0 节的宽度/高度预算），不给滚动就是**底排被直接裁掉且无处可去**。
  只有「概览」页签套滚动容器；说明（长文）、历史（官方 `List`）、
  空间与同步设置（各自带 `*_scroll`）已经能填满自滚，**别再套一层**。
* **底排两张卡顶对齐。** `h_flex()` 默认 `items_center()`，磁盘卡一行、变更卡六行，
  居中会让它们顶边错开、像两张卡各自飘着。这里用 `items_start()`
  ——**不是 `items_stretch()`**：磁盘卡就该是磁盘卡那么高，撑成空大盒子更假。

> **给基座的交叉轴不对称记一笔（D41）**：`gpui_kit::base::h_flex()` 装的是
> `items_center()`，而 `v_flex()` **不装任何交叉轴对齐**（= stretch）。
> **两者不是镜像关系**——一行里放一个列容器，列容器拿到的是**内容高度并被垂直居中**，
> 不是行高。壳层那一行挂了导航轨 / 主区 / 检视抽屉三样，少了 `.items_stretch()`
> 三样一起塌，表现为整屏上方一大块空洞。

「空间」页签是 `space::SpaceReport` 的完整呈现，四段：
总占用（一级目录构成条 + 图例）→ Top 10 大文件 → 可清理的构建缓存 → `.gitignore` 建议。

**清理与 `.gitignore` 都逐项给按钮，不给"一键全清"。** `delete_cache_dir` 本身有白名单
（core 只放行固定几个目录名），但一次删掉三四个目录意味着用户要重新构建才能继续干活；
`.gitignore` 是**写用户的仓库文件**，一次塞进去四条规则更没人记得住。
逐项点，用户每一步都知道自己干了什么。

**日志不在主区**——在右侧检视抽屉第一页签（见 3.4.1）。

### 3.3 第三方仓库详情

**是档案页，不是工作台**。第三方仓库只读跟踪：这里不跑命令、不改历史、
不清理磁盘。但**必须有日志**——用户要能看见每次拉取/检测到底发生了什么，
"只读"不等于"无反馈"。

**骨架与我的仓库完全同一个**（仓库头 + 页签 + 检视抽屉里的日志，见 3.2），
不另开一套页面；差异只在**页签内容按归属裁剪**：

| 页签 | 第三方仓库里 | 与我的仓库的差异 |
|---|---|---|
| 概览（默认） | 同步卡（**只有「拉取」「检测」两键**）+ 仓库档案卡（近 30 天活跃度 + 语言构成 + 一个「看完整说明」入口） | 去掉命令卡、分叉条、提交并推送 |
| 说明 | README（`TextView::markdown`） | **无差异** |
| 历史 | 最近提交列表 → 点行进 Sheet | **无差异** |
| 空间 | **不出现** | 我的仓库才有磁盘清理 |
| 同步设置 | **不出现** | 我的仓库才有定时自动同步 |

仓库头与我的仓库同款：仓库名 + 归属徽标 + 路径/分支/最后提交 + 右侧四个图标
（打开文件夹 / 开终端 / 云端主页 / 复制地址，见 3.8）。

**同步卡只有两键**是硬边界：第三方仓库是"盯着别人进度"，
推送与提交在这个语义下都不成立。 同步卡下半区放一行只读明细：
当前分支 / 跟踪分支 / 是否落后 / 最后同步时间（官方 `DescriptionList`，4 列一行）。

> ⚠️ **「推送」不能以任何形式出现在第三方仓库上**，包括旧实现里那一条
> 380px 的独立同步面板。阶段 8 的记录以为它已经删掉，实际当时还留在代码里，
> 阶段 9 真删了：同一屏里出现第二对同步键，两边各自改状态机，迟早对不上。

README **不进概览**。它已经占了「说明」页签整页，再在概览摊一份预览，
同一份 markdown 就有了两个渲染入口，哪天改样式只改得掉一半。
概览只留一个跳「说明」页签的入口。

检视抽屉的「历史」页签**不复制列表**，只给"最近一条标题 + 一个
「在「历史」页签里看」按钮"（路线表 D21）：抽屉 320px 放不下提交列表，
而复制一份的话两处会对"哪些提交、哪一条被打开"给出不同答案。

→「说明」「历史」两类仓库同款，这是刻意的——用户读自己项目的 README
和提交历史的需求，跟读第三方的一模一样，砍掉只是界面更薄，没有收益。


### 3.4 日志与状态反馈（两类仓库一致）

**所有耗时操作都必须有状态可见**。这是硬规则：用户点下任何会跑一会儿的按钮，
界面上必须同时出现"正在做什么"和"做完了什么"。

#### 3.4.1 日志区

日志区**两类仓库完全同款**（同一个组件，同一套状态机），区别只有
"跑什么会往里写"。放在仓库详情页右侧**检视抽屉的第一页签**，
不是主区平铺——主区留给执行层与命令层。

结构（自上而下）：

| 区域 | 内容 | 说明 |
|---|---|---|
| 状态行 | 当前操作 + 状态点 | 空闲 / 进行中 / 成功 / 失败 |
| 进度条 | `Progress` | 拉取、克隆有百分比；跑命令无百分比，用不定态 |
| 输出流 | 浅色底等宽区 | 见下方配色 |
| 结论行 | 一句话结论 | 成功时只在状态不可见时才补 |
| 工具行 | 复制 / 清空 / 在终端打开 | 三个都常驻，不藏悬停 |

**配色**：浅色底（`muted.background`）+ 1px `border`，等宽字体 `mono_font`，
**不要深色代码块**（这是灰白调界面唯一的杂色来源）。
错误行用 `danger.foreground` 前缀标色，**不要整段染红**。

#### 3.4.1.1 日志按仓库路径存（D7）

**不是一个全局对象，是 `HashMap<String, LogState>`。** 三条理由：

1. 切仓库不该把上一个正在跑的输出冲掉——`select()` 里**不许**有"清日志"，
   跑到一半切走再切回来要能接着看。
2. 后台线程回来时用户可能已经切到别的仓库了。往"当前选中"名下写，
   会把 A 的结果记到 B 的日志里。
3. 所以：**读**用 `Shell::log()`（当前选中的那份，没记录回落到 `LOG_EMPTY`），
   **写**一律用 `Shell::log_of(path)`（显式给路径）。写的时候拿 `log()` 一定是错的。

`LOG_EMPTY` 是模块级 `static` 而不是 `impl` 内的——`impl` 块不允许 `static` 项，
而且模块级常量能直接取地址，`unwrap_or(&LOG_EMPTY)` 不会每帧造一个临时值。

> ⚠️ 状态条报的是"**有没有活**"（取任意仓库的日志，文案「运行中 · <仓库名>」），
> 不是"当前仓库有没有活"。用户站在总览页盯着侧栏时，想知道的是这机器上还有没有东西在跑。

**进日志的操作**（两类仓库各一份）：

| 操作 | 我的仓库 | 第三方仓库 | 进度 |
|---|---|---|---|
| 检测 | 有 | 有 | 有 |
| 拉取 | 有 | 有 | 有 |
| 推送 | 有 | — | 无 |
| 提交并推送 | 有 | — | 无 |
| 一键运行命令 | 有 | — | 无 |
| 磁盘扫描 / 清理 | 有 | — | 无 |
| 分叉变基 / 撤销 | 有 | — | 无 |

进度来源：`net::progress_hooks` 解析 git 的 stderr，
`ProgressEvent { stage, detail, percent }`。**没有 `percent` 的走不定态进度条**，
不要拿假百分比糊弄。

⚠️ `ProgressEvent` 在共享缓冲里要**单独走一路**，不要拍平成字符串塞进输出流。
拍平之后"拉取"和"检测更新"在输出流里长得一模一样，而它们的阶段差别正是用户想看的。
（`gui/src/ops.rs` 的 `LogEvent` 就是 `Line` / `Stage` 两个变体。）

#### 3.4.1.2 停止

日志区工具行与 `Ctrl .` 共用 `Shell::stop_current` 一个入口，**别各调一次 core**：

| 操作类别 | 停法 |
|---|---|
| `Op::Cmd(_)` | `run_cmd::stop_repo_cmd()`（整树杀，不留孤儿 `node`/`cargo`） |
| 其余（拉 / 推 / 检测 / 变基） | `git::request_cancel()` |

两个入口都是**进程级全局**的（core 同一时刻只放一个忙操作），
所以 `stop_current` 不按仓库分：有活就停，活是谁的不影响结果。
停止按钮**只在跑的时候出现**——平时摆一个点不动的停止键只会让人去试它。

#### 3.4.2 仓库级状态徽标

侧栏仓库行上，除状态点外再挂一枚**仓库级徽标**，表示"这个仓库最近一次操作的结果"。

**一个位置、四种形态，按优先级互斥**——240px 的行塞不下第二枚胶囊：

| 优先级 | 徽标 | 含义 | 取色 |
|---|---|---|---|
| 1 | 进行中 | 有操作在跑（官方 `Spinner` 转圈） | `tier3` 灰蓝 |
| 2 | 失败 | 上次操作失败 | `danger` 红字 + `red_bg` 浅红底 |
| 3 | 走代理 | 上次网络操作靠代理才通 | `orange_text` + `orange_bg` |
| 4 | 分档徽标 | 见 2.3（可更新 / 已分叉 / 待推送 N / 未提交 N） | 见 2.3 |

**分档信息并没有因此丢失**——左侧那个字形（2.3）已经带着同一份 `bucket_of` 的结果。
优先级这么排的理由：跑着时最需要知道的是"在跑"（不然会去重复点），
跑完了最需要知道的是"成了没有 / 是不是绕了代理"。

「走代理」是内核 `OpResult.used_proxy` 的一等信息，值得单列：
用户经常需要知道"为什么这次慢"。**代理地址直接写在胶囊上**
（`代理 127.0.0.1:7897`）——这一列只有 320px，塞不下"一个图标 + 一句
tooltip 之外的信息"，而这串地址恰恰是排查网络时最需要的。

#### 3.4.3 克隆的状态

克隆是**新增仓库**的操作，没有仓库上下文，所以它的状态**不进日志区**，
走独立的克隆对话框：

- 对话框内自带进度条 + 阶段文字（`ProgressEvent.stage`）+ 实时输出。
- 成功 → 关对话框，通知「已克隆 X 个仓库」，**侧栏自动展开对应分组并定位**。
- 失败 → 对话框不关，错误留在输出里，保留用户填的地址。
- 取消 → `git::request_cancel()`，对话框内明确显示"已取消"。

### 3.5 两类仓库的功能边界

这张表是硬边界，**越界就是设计缺陷**：

| 能力 | 我的仓库 | 第三方仓库 |
|---|---|---|
| 拉取 / 检测 | 有 | 有 |
| **日志区** | **有** | **有** |
| 推送 | 有 | 无 |
| 提交并推送 | 有 | 无 |
| 分叉变基 | 有 | 无 |
| 一键运行命令 | 有 | 无 |
| 磁盘清理 / .gitignore 建议 | 有 | 无 |
| 定时自动同步 | 有 | 无 |
| 空间页签 | 有 | 无 |
| 同步设置页签 | 有 | 无 |
| 说明（README）/ 语言 / 活跃度 / 最近提交 | 有 | 有 |
| 复制远程地址 / 云端主页 | 有 | 有 |
| 打开文件夹 / 开终端 | 有 | 有 |
| 编辑 / 移除 / 重命名 / 移动归属 | 有 | 有 |

注意三点与旧版的差异，本次修正：
- **日志区两类都有**（旧版把第三方的输出区删了，是错的）。
- **README / 语言 / 活跃度 / 最近提交两类都有**——我的仓库自己也需要看
  README 和提交历史，这不是第三方专属。
- **复制远程地址 / 云端主页两类都有**（旧版只给了第三方，是错的）。

### 3.6.1 主题为什么不给开关（阶段 11 判定）

这一版界面只有**一套**配色，写在 `gui/theme.json`（"改配色只动这一个文件"
是本文的硬约定）。给一个"深色"开关却拿不出配套的深色 token，点下去只会
切到基座自带的默认深色——那既不是本应用的配色，也与 4.1「不要深色面板」
直接冲突，界面会从"灰白调"整个翻到另一套色系。

所以设置对话框里把主题做成**一行只读**（`DescriptionList` 两列：
主题 = 浅色 · 灰白，配色出处 = `gui/theme.json`），并说明原因。
`Settings.theme` 字段保留——两套界面共用同一份 `config.json`，搬回旧界面仍生效。
**真要做深色是"新增一套 token"的活，不在收口范围。**

> **core 侧已经删掉的东西**（阶段 9）：`repos::ReadmePreview` / `read_readme` /
> `parse_readme`。它们是为"概览卡只展示标题 + 首段"那套提炼逻辑写的，
> README 改由「说明」页签整篇渲染之后没有调用方。`find_readme` 保留
> （`read_readme_text` 与 `readme_file_name` 共用它）。


## 3.7 「提交并推送」怎么安排

**位置**：同步卡里，**紧邻「推送」但不是第四个并排按钮**。

原因：三键（拉取/推送/检测）是高频、位置固定的执行层操作，用户靠肌肉记忆按位置；
提交并推送是低频、且要先填提交信息的多步操作。把它并进三键会让同步卡变宽，
并让"点一下就完事"的节奏被一个需要输入的按钮打断。

**形态**：`折叠态`「提交并推送…」在同步卡下方**一行**（宽度自适应，不进三键行）；
点开 → 官方 `Dialog`：

```
┌ 提交并推送 ─────────────────┐
│  ┌ 变更摘要 ─────────────┐  │
│  │ M src/main.rs         │  │
│  │ A src/new.rs          │  │
│  └───────────────────────┘  │
│  提交信息 *                  │
│  ┌───────────────────────┐  │
│  │ 更新登录页样式          │  │
│  └───────────────────────┘  │
│  ☐ 提交后拉取                │
│  ┌──────┐  ┌─────────────┐ │
│  │ 取消 │  │ 提交并推送   │ │
│  └──────┘  └─────────────┘ │
└────────────────────────────┘
```

- 提交信息**空不能提交**，但**不做"禁用按钮"**：官方 `Dialog` 的 `footer` 是
  **一次性元素**（签名就是 `impl IntoElement`，不随帧重画），禁用态没有地方挂；
  要挂就得自己每帧重建 footer，那会丢按钮焦点。所以改成**点下去就地报一行红字**
  （`dialogs/commit.rs`），对话框不关、用户填的提交信息也还在。
- 提交信息预填上次同仓库的提交标题（`git log -1`），用户改比从零写快。
  预填走 `InputState::set_value`——**它确实存在**，见 3.2 那条更正。
- ☐「提交后拉取」**默认勾上**：本地落后时 `push` 必被拒（non-fast-forward），
  而"忘了先拉"是最常见的卡点。勾上之后 core 会在 commit 之后、push 之前
  插一次 `--ff-only` 拉取（`sync::commit_push_with` 的 `pull_first`）。
- 变更摘要的行**不给 git 的两字母代码**（`M` / `A` / `??`），给「已暂存·修改」
  「未暂存」「未跟踪」这样的词：只有天天敲 git 的人认得字母，而这一列要回答的
  是"这次提交带不带它"。排序是**已暂存优先、其余按路径**——
  git 的原始顺序随文件系统变，同一份改动两次打开列出来的次序不一样，
  会让人以为多了或少了东西。摘要最多列 60 条，末尾给"还有 N 个…"。
- 走的是 `sync::commit_push_with`，与其他网络操作**同一条 `run_net_op`** 链路
  （直连 → 代理回退、认证注入、进度解析全部复用，不另起一条）。
- **仅我的仓库有**。第三方仓库出现这个按钮即为越界。

## 3.8 「跳转到本地页 / 云端」怎么安排

先厘清这两个词指什么——它们在 git 里其实是**四个不同的动作**，
混成"跳转"会做出一个语义模糊的按钮。这里按对象明确拆开：

| 用户想做的事 | 实际动作 | 入口 | 归属 |
|---|---|---|---|
| 打开本地仓库文件夹 | 调系统文件管理器 | 仓库头 `打开文件夹` 图标 + 右键菜单 | 两者都有 |
| 在终端里进这个仓库 | `cd` 到路径并起终端 | `Ctrl T` + 仓库头终端图标 | 两者都有 |
| 看云端仓库主页 | 打开 `remote_url` 的网页 | 仓库头 `云端主页` 图标 | 两者都有 |
| 复制克隆地址 | 复制 `remote_url` | 仓库头复制图标 | 两者都有 |

**安排**：

- **「打开文件夹」与「云端主页」放在仓库头右侧**，做成两个图标按钮
  （`Folder` / `ExternalLink`），各自带 tooltip 写明"本地"还是"云端"。
  它们是同一类"跳出去"的动作，视觉上并排才成组。
- **「云端主页」是唯一允许用 Link 样式的地方**——它真的离开本应用去浏览器。
  按设计规范：Link 只给外部 URL，其余一律 Button。仓库地址来自
  `net::remote_url`，仅当 `RepoStatus.has_upstream` 为真时才显示（没有上游就没链接可跳）。
- **不设「本地页 / 云端页」这种二级视图**。本应用没有"云端页"这个页面，
  造一个只会让用户以为能在应用里浏览云端仓库，那是假入口。
- 私有仓库的云端主页可能 404，但**不隐藏按钮**——隐藏会让用户以为功能坏了。
  打开后由浏览器给真实反馈。

**克隆地址的展示**：仓库头放一个只读地址条显示 `remote_url`（手写，理由见 3.2 的
说明框——官方 `InputState` 装不进静态值），复制走仓库头第四个图标按钮。
这样"看地址"和"复制地址"不用两个不同控件，也不摆两个复制入口。
第三方仓库尤其需要——你多半是为它才存进来的。

## 3.9 「打开仓库说明文档」怎么安排

指 README。**两类仓库都有，且必须同款**（我自己的项目也要读它的 README）。

**位置**：详情页的**页签**，不是主区的一个大区块。

理由：README 可能很长，主区被它占满就没法同时看同步状态；
而页签天然是"这块内容很长、需要切换查看"的容器。

**形态**：

```
仓库头（常驻）
├── 概览    ← 默认页签：同步卡 + 命令卡 + 磁盘
├── 说明    ← README，TextView::markdown
├── 历史    ← 最近提交列表 → 点行进 Sheet
└── 空间    ← 磁盘占用 / 大文件 / 缓存清理 / .gitignore 建议
```

- 默认停在「概览」——那是干活的页，不是读的页。
- 「说明」用 `text::TextView::markdown`，保留标题层级；
  README 很长时在页签内滚动，**不撑高页面**。`TextView` 是 markdown 解析器，
  自己拿 `div` 拼标题和段落不是选项——README 里的表格、代码块、引用块会立刻露馅。
- 页签顶部一行来源标注（读到的是 `README.md` 还是 `README.rst`）+
  一个「在文件管理器中查看」按钮。
- **概览页不摊 README 预览**（路线表 D22）。同一份 markdown 有两个渲染入口的话，
  哪天改样式只改得掉一半；概览只留一个跳「说明」页签的入口。
- 没有 README（`read_readme_text` 返回 `None`）时用官方 `Empty` / `EmptyHeader` /
  `EmptyMedia` / `EmptyContent` 给**可操作空态**：
  「这个仓库没有说明文档」+「仓库根目录里没找到 README.md / README.txt / README.rst」
  + 一个「在文件管理器中查看」按钮——空态要给下一步，不是只说"没有"。
  侧栏没仓库、克隆没结果等空态一律同一个组件。
- **超长要截断并说清楚**。`TextView` 要把整篇解析成布局，一份十万字的 README
  会在打开页签的那一帧卡住界面；core 在 `README_MAX_CHARS`（120k 字）处截断
  并在文末留一句"README 太长，已截断"，界面照实显示——静默截断等于骗用户。
- 「空间」页签里含 `add_gitignore_entries` 的建议应用入口（见 3.6）。

**页签用官方 `tab::{Tab, TabBar}`**，选中态由组件自带，不要自己画。


## 3.10 「克隆仓库」怎么安排

指从远端地址把仓库拉到本地。**两类仓库都能克隆**（用户的项目可能还没推上去，
先克隆别人的也很常见），克隆完默认进「我的仓库」分组，用户可随时改归属。

**顺序不能反（D5）：先 core，后界面。** 克隆是网络型 git 操作，
必须走 `net::run_net_op`——直连失败自动探测代理回退、凭证注入、
传输停滞保护都在那条链路里。GUI 侧自己拼 `Command::new("git")` 会把这三样全绕过去。

**位置**：侧栏脚那颗「克隆仓库」按钮 → 一个独立 `Dialog`。
不塞进「添加仓库」那个对话框：那个是"把已经在磁盘上的目录登记进来"，
克隆是"先从网络取回来"，两者字段几乎不重叠，挤在一个结构体里只会让两处各自判有没有。

**对话框形态**（自上而下三段）：

```
仓库地址   [ https://github.com/user/repo.git      ]
克隆到     [ F:/AIwork/                            ]
提示        支持 https / ssh / git@host:owner/repo 三种写法…
────────────────────────────────────────────
阶段词 · 百分比                                     取消  [开始克隆]
[ 不定态进度条 ]
[ 实时输出（浅底等宽，上限 200 行） ]
```

- 目标父目录**预填当前选中仓库的父目录**；一个仓库都没有时退回家目录。
  绝大多数用户的仓库都住在同一个目录下，从那儿克隆最省事。
- 焦点直接落在地址上——这是这个对话框里唯一必须先填的字段。
- **跑起来时「取消」变成停止**（接 `git::request_cancel()`），不关窗：
  要让用户在输出里看到「已取消」这三个字。第二次点「取消」才是关窗。
- **失败时对话框绝不关**：地址还留在输入框里，用户改完就能重试；
  关掉的话他得把刚才那串地址重新敲一遍。
- 成功 → 关窗 + 一条通知 + 侧栏自动展开对应分组并定位到新仓库。

**错误文案要给"该改什么"，不只是"失败了"**。五类各一句：

| 情形 | 文案方向 |
|---|---|
| 被取消 | 克隆已取消（**必须排第一**，取消时 stderr 里没有仓库线索） |
| 代理模式没找到可用代理 | 确认代理软件已运行，或去设置里手填地址 |
| 直连打不开且没有代理兜底 | 无法连接远端，且未找到可用代理（**排在认证前面**——连不上时 git 有时也会问用户名） |
| 私有仓库 | 确认已在本机 Git 凭证管理器中登录 |
| 仓库不存在 / 无权访问 | 仓库不存在或无权访问 |

每一条后面都附 git 原始 stderr：结论给方向，stderr 给"到底发生了什么"，两者都要。

**地址解析的边界**（core `repos::repo_name_from_url`）：仓库名会直接成为磁盘目录名，
所以 `host/owner` 那一段之后还得有东西才算仓库地址（`https://github.com/user/`
是**用户主页**，拿它当目录名会克隆出一个叫 `user` 的目录再报"仓库不存在"，
用户完全不知道该改哪），`.` 与 `..` 也单独挡掉——它们的字符都在白名单里，
但会让目标目录指到父目录去。

四张卡（卡间 6px，§3.11.2），②号卡按工具状态三态切换：

### 3.11.4 图标三级降与「可更新」出口

图标三级降（设计 §10.1 拍板）：① Provider 自报（**没接**——三家输出里没有图标

「可更新」在界面上有**两个出口，判据只有 `latest.is_some()` 一个**：
组标题行尾橙点（组内有可更新项）、档案头「可更新 x.y.z」徽章（warn-wash 胶囊，
与侧栏 / 总览同一档）。`latest` 两个数据来路：winget 的 `list()` 免费带回，
其余靠 `ops::check_cli_updates` 在**扫描落地之后单独派发**（要走网络，压进扫描
就是"进屏先等几秒"——先渲染、后台再刷）。

### 3.11.5 中栏四卡逐卡规格

**① 档案头**（恒画，约 108px）：24px 图标块 + 大名 + 版本 / 提供者 / 桌面关联
徽章行 + 事实行（命令 · 提供者 · 首次安装 · 数据目录；**超宽字段整行放，不截断**）。
升级执行态自动收事实行，把首屏让给执行态。

**② 更新与卸载**（三态，规格见 §3.11.1 表）：就绪态卡底双键——「升级到 x.y.z」
**只在真有新版时画**（`latest.is_some()` 且 provider 给得出升级命令）——画一颗
升不了的键是骗人的键；「卸载」恒画，用 danger（不可逆动作不鼓励点）。两颗的
忙态判据是 `cli_busy_any()`：**任何一个** CLI 操作在跑就两颗一起禁，不只是这
一颗——两颗一起跑会在同一个包管理器上撞车（§3.11.6 串行锁）。

**③ 操作日志**（终端形态，2026-10-14 v8 定稿）：与仓库屏日志同组件，但**默认
展开为终端形态**——`$` 提示符 + 等宽输出流 + 行末状态（`✓ 00:12` / `进行中…` /
`等待`，当前执行行 info-wash 高亮）+ 标题行右侧复制 / 清空 / 在终端打开三钮。
`flex_1 + min_h_0` 吃掉剩余高度；就绪态可收起成一条摘要（「操作日志」+ 最后
一句结论）。滚动句柄必须用 `cli_log_scroll`——与仓库日志共用一个 `ElementId`
会共用同一个滚动句柄（在 CLI 屏滚一下，概览页的日志跟着跳）。升级 / 卸载 /
清理的**每一步**同时进两处：屏上这份日志，与 `diag::note` 的 app.log
（release 无 stderr，显式捕获通道，设计 §11）。

**④ 磁盘占用**：Provider 级共享缓存（npm 缓存 / pnpm store / cargo registry…）
**不属于任何一颗包**，与程序 / 缓存 / 数据合成一张卡：标题行右侧合计 + 构成条
（与仓库屏"语言技术栈"同形）+ 图例 + 分项行（路径 + 体积 + 行尾「清理」或
「共用 · 保留」锁标）+ 卡底「一键回收 x GB」（只回收可安全清理的那些）。
两条路都过同一个确认框（`dialogs/cli.rs`），删之前报合计字节——**有一项没量过
就显「计算中…」，不拿量过的那些加出一个数来**（Q39 那一族）。误清的代价说在
框里：可再生，但下次安装 / 更新要重下（本机 npm 缓存 18.8 GB）。

### 3.11.6 串行锁与确认框

**同一时刻只放一个 CLI 操作**（设计 §11 串行）：`cli.busy`（包 id）/
`cli.shared_busy`（缓存路径）两个忙集，任一非空 ⇒ 所有入口键禁用。

**v8 定稿：卸载审计从模态框搬到中栏 ② 卡的一态**（2026-10-14 用户令「卸载不需要
选择那些东西跟着一并卸载的吗」）。`dialogs/cli.rs` 卸载框原来的四段层级
（① 同时移除清单，core `affected_notes`，四档桌面关联四句话 → ② 等宽命令预览
`plan.steps`，不可编辑 → ③ 风险徽章三档 → ④ 可勾选清理清单，Cache 默认勾；
Config·Data 换锁图标 + 红字，**不画灰勾选框**——官方 Checkbox 没有禁用档）
**整体上浮到中栏**：七项勾选、锁定项、依赖倒查、备份选项、solid danger
「确认卸载 · 释放 x GB」全在这一页完成，**不再弹第二层模态框**——"确认即执行"
的一页式审计。确认后 ② 卡转为卸载执行态，每步结果实时回显到 ③ 终端日志卡。

**卸载执行态（2026-10-15 落地，`cli::execute::run_plan_live` + ② 卡步骤管道）**：纵排步骤列表（1 条卸载命令 + N 条勾选清理，步骤数不定 ⇒ 不放横排），每行 = 态点 + 标签（core 拼）+ 细节（释放字节 / 失败原因，有才画）+ 计时格；态点与六态画法和升级管道**同一张表**（`cli_tab::pipe_parts`）。取消键执行中可点：正在跑的卸载命令被杀记「已取消」、还没轮到的连同记上；前一步失败而没跑到的记「未执行」——两档分开，混一档会把失败说成用户取消。收尾即清回 ready 态，结论（三种终局 + 清理释放合计）在 ③ 卡与通知里。**依赖倒查已落地**（2026-10-15，待建 #3）：审计页第五段画 WARN_WASH 警告条——`plan.rs::dependents_of` 以**目录前缀**判据（被卸载者的安装目录严格包含另一包的安装目录，如卸 `winget:Node.js` 废掉 `nodejs\node_modules` 下的全部全局 CLI）从扫描数据现派生，**查不出连带就不说有连带**（有一边拿不到 install_path 不判；管理的包不在管理器自己目录之下——设计稿的 bun 例子——也查不出，不编警告）；空表不画这一段，名单最多点四个名。**备份选项仍未画**（待建 #7）。落地实况与偏差登记在 `roadmap/cli.md` 阶段四「卸载执行态阶段化」「依赖倒查」两节。

**共享缓存清理仍走确认框**（④ 卡行尾「清理」与卡底「一键回收」）：合计一行 +
逐项清单（超出 8 条并一句）+ 后果提醒（可再生 / 要重下），danger「清理」。
winget uninstall 是分钟级 ⇒ 执行中的确认框**不关**，确认键转「执行中…」，
跑完由 render 帧收框 + 弹通知（后台任务里没有 `&mut Window`，与
`pending_batch_note` 同一条路）。

执行前**用当下清单按 id 重建计划**：审计页开着的时候后台可能重扫，快照里的版本与
目录可能已经变了；包没了或给不出命令 ⇒ 确认键禁用 + 一句通知，**不开空执行**。

（浅色画布 `#E8EDF0`、描边 `#D7E0E4`、品牌 `accent.background` `#0E4F55`，深浅两套主题）。
**wash 那三个帮手函数没有删**（`orange_bg()` / `blue_bg()` / `red_bg()` 仍在
`gui/src/tokens.rs` 定义、仍在使用），只是它们的数值不再在这里复述。
颜色一类的完整清单见 `docs/UI-DESIGN-v4.md` §1。

**去深色**：输出区深色代码块改浅色底；`primary.background` 墨色按钮只在 唯一的决定性提交上用（表单提交、变基确认），日常操作用 `default` / `outline` / `ghost`。 品牌 Bird 图标保留墨色方块，仅出现在标题栏。

**颜色是稀缺资源**：一个区域内最多一处强色。状态点、徽标、按钮不要同时上色—— 先靠结构（位置、间距、字重）建立层级，颜色只留给真正改变用户注意的地方。

### 4.2 档位表（禁写裸数字）

字号 `FS\_\*`、圆角 `R\_\*`、间距 `GAP\_\*`、图标 `ICON\*` 四组常量已定义在 `gui/src/tokens.rs`（⚠️ 早先写的是 `shell.rs`，阶段 1 拆文件时搬走了，这行没跟着改）。
**原则是"沿用不新增"，但表本身漏过的关系要补进来**——阶段 11 复查时发现
「一串同类元素相邻两项之间」既不在语义表里、代码里也全是裸数字
（5 处 `gap(px(2.0))`），于是补了 `GAP_DENSE` 这一档。**不补的后果不是"多一个
常量"，而是那一类关系永远没有出处，下次有人写 1px 也没人知道该是几**。

⚠️ **本表与下面那张「间距语义」表已作废并删除**（2026-10-12）。它们列的
FS_BODY 13 / R_LG 8 / R_XL 12 / GAP_LG「卡片内区块」**全是旧值**：字号实际走
`UiScale::metrics()` 的三档（小 / 中 / 大，`gui/src/tokens.rs`），圆角
`R_LG`/`R_XL` 读 `theme.json` 的 `radius`/`radius.lg`（**14 / 20**），间距只保留
`GAP_DENSE`（一串同类元素相邻两项）与 `GAP_TIGHT`（两个不同东西之间）这一条分界。
**完整档位表与语义表在 `docs/UI-DESIGN-v4.md` §3**，本文件不复述任何数值
（「一条视觉规则只允许有一个家」）。

⚠️ **`GAP_DENSE` 与 `GAP_TIGHT` 不是"大一号 / 小一号"的关系**，别互相顶替：
`GAP_TIGHT` 说的是**两个不同的东西**之间的关系（图标与文字、标题与说明），
`GAP_DENSE` 说的是**一串同类元素**里相邻两项的呼吸量。混用会出现"标题离它的
说明比离上一段正文还近"这种反直觉的版面。

**嵌套圆角**用 `内圆角 ≈ max(0, 外圆角 − 间距)`，保证同心。 GPUI **不会**因为父级有圆角就裁剪子级，嵌套面要各自带自己的圆角或显式 clip。

### 4.3 图标

只认一套：`use gpui_kit::assets::IconName as AssetIcon`（完整 lucide + 品牌 Bird）。 **不要用 `component::IconName`**——那是另一套，线宽与视觉重量不同，混用一眼就不齐。

尺寸走 `icon_sm()` / `icon_md()` 两个包装函数，**不写 `.small()`**（两套默认尺寸不一致）。

纯图标按钮必须：

* 图标显式 `.text_color(tier3(t))`（幽灵按钮默认继承墨色，观感"太深"）；
* 配官方 `Tooltip`（`Tooltip::new(..)`，不要手写 `on_hover` 弹提示）；
  带快捷键的再挂一枚官方 `Kbd`（`Kbd::new(keystroke)`），
  **不要自己拼"Ctrl B"这样的字符串** —— 官方 Kbd 的键帽样式和间距是对齐过的；
* 配 `accessibility_label`；
* 不用于陌生动作——图标不能替代文字去猜意思。

同一屏不出现两个语义相同的图标（这是"重复功能项"的一种）。

## 5\. 交互状态

每个可交互元素都要有：常态 / 悬停 / 按下 / 聚焦 / 选中 / 禁用 / 加载 / 错误。

* **悬停**：gpui 没有 CSS `:hover`，靠 `on_hover` 记状态重画（`Shell.hovered`）。 带 `on_hover` 的行返回 `Stateful<Div>`。
* **选中**：用元素自身的面 + 更强前景色。**导航轨这类 ghost 图标按钮的选中面走
  `tokens::selected_mask`（D60）**：`foreground.opacity(0.08)` 的一层**半透明遮罩**，
  不是实色。0.08 由色板里的「选中面」#EDEBE7 反推而来，叠白卡得 #EDEDED，
  与侧栏仓库行的选中面 1:1 不可分。选遮罩而不填实色，是因为**实色换个底就不对、
  遮罩在任何底上都成立**。 **禁止**用左侧竖条或单边框做选中标记——那是 web 模板习惯， 会破坏圆角轮廓，且在这条本来就对齐文字列上多出一条竞争边。
* **禁用**：降低强调，**不给悬停/按下反馈**（否则用户以为能点）。
* **加载**：`Skeleton`（带呼吸动画），形状要接近真实内容。 内容其实已就绪的切换**不要**用骨架屏。
* **焦点**：键盘焦点环必须可见；浮层关闭后焦点回到触发点。
* **危险操作**：可逆的走"执行 + 通知撤销"（移除仓库）； 不可逆的才用 `AlertDialog`（丢弃变基后的提交），确认框标题写清对象与后果。

指针约定：按钮、菜单项、复选框用默认箭头指针；只有真链接用手型。 悬停才出现的按钮只能是快捷入口，**关键动作与危险动作不许只藏在悬停里**。

## 6\. 功能分层（防重复的总规则）

改动界面先给功能定层，层位决定位置。**同一层里一个动作只出现一次**。

| 层 | 内容 | 位置 |
|---|---|---|
| 执行层 | 拉取 / 推送 / 检测（三键）、提交并推送 | 详情页同步卡 + 其下一行 |
| 命令层 | 四条命令 + 钉住的自定义命令 | 详情页概览页签 |
| 查看层 | 日志 / 变更 / 历史 / 空间 / 说明 | 检视抽屉 + 内容区页签 |
| 低频层 | 打开文件夹 / 终端 / 云端主页 / 切仓库 / 设置 | 仓库头图标 + ⌘K |
| 列表层 | 添加仓库 / 克隆仓库 | 侧栏底部 |

**导航轨不属于任何层**：它只回答"我在看哪一屏"。 **不要往导航轨塞功能入口**。

### 6.1 唯一入口对照表

同一件事只能有一条主路径，其余都是它的镜像：

| 动作 | 主入口 | 镜像（不得新增第三处） |
|---|---|---|
| 拉取 / 推送 / 检测 | 详情页同步卡 | ⌘K「当前仓库」、快捷键 1·2·3 |

| 重命名 / 移除 | 右键菜单 | ⌘K「当前仓库」（阶段 11 补，见 D30） |
| 编辑仓库 | 右键菜单 | 添加对话框内复用同一表单；⌘K「当前仓库」（阶段 11 补） |
| 打开文件夹 / 终端 | 仓库头图标 | 右键菜单、⌘K（`Ctrl T`） |
| 云端主页 / 复制地址 | 仓库头图标 | 右键菜单 |
| 添加仓库 | 侧栏底部 | ⌘K |

| 看上次批量结果 | ⌘K「低频动作」的「上次批量结果」（无记录时置灰） | 跑完那条通知会消失，这一项是逐仓库结论唯一的读出口（D35） |

| 卸载一颗 CLI 工具 | CLI 屏更新与卸载卡「卸载」→ 卸载审计页（§3.11.6，一页式审计不弹第二层框） | 无——不可逆动作不摆第二个入口 |

### 6.2 已删除的重复项

* 总览页的复选框与底部批量条 → **移除**。批量是独立任务， 混进"看统计"会让总览页承担两个任务。批量改由 ⌘K 承载， 与总览页解耦。**形态已定（Q3）**：⌘K「批量同步」里**固定三条命令 + 按分档自动筛**（「拉取全部」只跑 `behind>0`、「推送全部」只跑 `!第三方 && ahead>0`、「检测全部」扫全部），**不是**"在列表里勾选再跑"——判断依据在状态扫描里已经算好，界面上再摆一套复选框等于把同一件事做两遍，而复选框那一套刚刚才从总览页删掉。
* 详情页标题栏的平铺图标按钮 → **收进检视抽屉**。主区只留执行层与命令层。
* 深色输出块 → **改浅色**（4.1）。

### 6.3 ⌘K 的分组顺序（2026-10-03 实机二轮定，D46）

```
低频动作 → 当前仓库 → 批量同步 → 切换视图 → CLI 工具 → 切到仓库
```

**长列表不能排第一。**「切到仓库」是唯一长度随仓库数增长的一组，
17 个仓库就能把面板可视高度吃光——排第一时打开 ⌘K 看到的是一屏仓库名，
其余四组要滚过 17 行才够得着，而那四组才是低频层真正要承载的固定命令。
仓库名靠**搜索**找（关键词里带名字 / 别名 / 路径 / 分支 / 归属），不靠滚列表找。

置顶「低频动作」还有一个理由：**新装、零仓库、停在总览时**，
「当前仓库」那 8 条会全是灰的，而用户此刻真正能做的（添加 / 克隆 / 设置 / 扫描）
就在低频动作里。

⚠️ 改顺序时把 `palette.rs` 的 `G_*` 下标常量、代码块的 push 顺序、
以及每个块尾的 `debug_assert_eq!` **三样一起动**——
`G_*` 只是标签，改它不会改顺序，只会让断言继续撒一个仍通过的谎。

## 7\. 文案

* 按钮文案说结果，不说手势：「保存」「移动」「删除」，不是「点击保存」「执行移动」。
* 确认框：标题写对象与后果 → `删除「Roadmap」？`；动作按钮用结果动词 → `删除`。 不用「确定吗」「是的」。
* 省略号用单字符 `…`，且**只给会打开弹窗 / 需要更多输入的命令**。
* 中文短标签不加句末标点；界面全中文，标点用全角。
* 同一对象全站同名：侧栏叫「我的仓库」，右键菜单、总览表格、通知里也叫「我的仓库」， 不出现「我的代码库」「自有仓库」等变体。
* 标题栏副行这类已由上下文说清的信息不再重复。

## 8\. 键盘

| 键 | 作用 | 范围 |
|---|---|---|
| Ctrl K | 命令面板 | 全局 |
| ↑ ↓ | 上下切仓库（到头就停，不绕回） | 全局。仓库页走侧栏当前组的可见行，总览页走表格行 |
| Ctrl B | 折叠 / 展开侧栏（总览页上 = 回到仓库页） | 全局 |
| Ctrl I | 折叠 / 展开检视抽屉 | 仓库详情页 |
| 1 2 3 | 拉取 / 推送 / 检测 | 仓库详情页（总览页让位） |
| Ctrl T | 当前仓库开终端 | 仓库详情页 |
| Ctrl . | 停止当前运行中的操作 | 有操作在跑时 |
| Esc | 关闭最上层浮层；本壳自己画的侧栏筛选框也归它收 | 全局 |

**`1·2·3` 按屏幕位置对位**（拉取 · 推送 · 检测），不是按操作顺序——
用户是先看见按钮再按位置的键。

快捷键的显示位置（阶段 11 落地情况）：

* **tooltip**：同步卡三键、仓库头终端键、检视抽屉收起/展开键、日志区停止键
  都走官方 `tooltip_with_action`，角标由官方从 keymap 查出来，
  **键位改了不会说谎**。
* **正文里的键位提示**（不是按钮 tooltip）走官方
  `Kbd::global_binding_for_action(&Action, &Window)`。目前只有一处：主区空态那句
  「找不到要的功能时按 `Ctrl K`」——D9 删掉标题栏搜索之后，**这一行是 ⌘K 全应用
  唯一的可见入口**，偏偏是最不能写错键位的一处。查不到时**退成不带键位的纯文字**：
  宁可少给一个提示，也不给一个可能已经失效的键位。
* **一条硬规则：界面上任何键位提示都从 keymap 查，不写死字符串。**
  写死的那份在改键之后就是一句假提示，而假提示比没有提示更糟——用户会照着一个
  不存在的键去找。（阶段 11 收尾复查抓到两处手写：日志区停止按钮与上面那句空态提示，
  均已改成查 keymap。改完 `gui/src` 里含 `Ctrl` 的字符串只剩 `KeyBinding::new` 那几行。）
* **右键菜单里不画角标**。官方的 `PopupMenuItem` 只为**带 Action 的条目**画 Kbd，
  而侧栏那套菜单的条目是带仓库路径的 payload 条目（详见路线表 D29）。
  替代方案是每条塞一个"待命"Action，那是假的提示，更糟。
* **替代保证**：右键菜单的每一条都有第二条键盘路径（⌘K「当前仓库」组，
  `Ctrl K` 进），符合本节"右键菜单不能是某个关键命令的唯一入口"这条要求。

所有右键菜单项必须有键盘路径——右键菜单**不能是某个关键命令的唯一入口**。

[`roadmap/archive.md`](./roadmap/archive.md)）**，本节只定顺序：

0. **地基核对**：`cargo check --workspace` 通过、确认官方 API 在当前依赖版本可用。
1. **壳**：标题栏 + 导航轨（总览 / 我的仓库 / 第三方仓库，顺序见第 1 节）
   + 检视抽屉骨架 + 状态条，窗口下限 1080×640。总览页先占位，**点它时侧栏收起**。
2. **侧栏折叠与拖宽**：`Sidebar` + `h_resizable` + `transition` + `reduce_motion`，
   宽度与折叠态落盘。这一步先放静态列表。
3. **侧栏树**：两组 + 仓库行 + 状态点/徽标 + 右键菜单（含移归属 + 通知撤销） + 底部「添加 / 克隆」。
4. **检视抽屉 + 日志区**：日志组件（两类仓库同款）+ 状态徽标 + 进度 + 停止按钮。
   **这一步优先于详情页**——详情页每个区块都要往日志写东西，先有日志后面才接得上。
5. **总览页**：页头 + 四张状态卡 + 活跃度 + 汇总表；移除复选框与批量条。
6. **详情页共用骨架**：仓库头（四个图标）+ 页签（概览 / 说明 / 历史 / 空间），
   两类仓库共用，页签内容按归属裁剪。
7. **我的仓库内容**：同步卡 → 分叉条 → 提交并推送 → 命令卡 → 磁盘摘要；
   空间页签（.gitignore 建议）。
8. **第三方仓库内容**：按 3.3 的裁剪表——同步卡只留两键 + 只读明细，
   说明 / 历史两页签同款，砍掉空间与同步设置。
9. **克隆**：先给 `crates/core` 补 `repo_name_from_url` + `clone_repo`（照搬 Tauri 版，见 3.10），
   core 测试通过后才做克隆对话框（地址输入 + 进度 + 阶段文字 + 取消）。
10. **收口**：⌘K、快捷键、补空态 / 错误态 / 长文案 / 更大字号下的复验。

**第 4 步提前的理由**：日志是所有耗时操作的出口，先修路再跑车。
**第 9 步 core 优先于界面的理由**：见 3.10，GUI 自己拼 git 子进程会绕过
`run_net_op` 的代理回退与认证注入。
