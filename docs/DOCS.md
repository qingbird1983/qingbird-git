# DOCS.md — 文档规范

**这份文件管"规矩写在哪儿、写哪一本、怎么改"**。它治的是本项目最贵的一类事故：
**一条规则有两个家，改一处漏一处，而两边各自看着都对**——两次实测过（文档里的
卡间距写 12 而实现是 6；`docs/UI-DESIGN.md` 那张 1495 行的设计规范里，
整张色板与整张档位表都是 2026-10 之前的值，却挂着"已定稿，实施时不再讨论"）。

---

## 1. 文档清单：每一本管什么、不管什么

| 文件 | 管什么（唯一家的内容） | **不管什么**（写进去就是第二真源） |
|---|---|---|
| `README.md` | 对外第一眼：这是什么、怎么跑起来、四道闸是什么 | 具体数值、版本号、测试条数（都会漂，**一律不复述**） |
| `AGENTS.md` | **纪律台账**：为什么会这样、踩过什么坑、判据是什么、发版流程 | 视觉数值（只在 v4）、代码风格细则（在 `docs/CODE.md`） |
| `docs/CODE.md` | 怎么下笔：文件/函数尺寸、命名、错误处理、日志、注释、提交信息、依赖 | 具体的坑与历史（在 `AGENTS.md`） |
| `docs/DOCS.md`（本文件） | 文档怎么分家、新增判据、路线表条目格式 | 具体数值与纪律细节 |
| `docs/UI-DESIGN-v4.md` | **视觉契约**：颜色 / 圆角 / 间距 / 阴影 / 动效 / 图标这六类数值 | 版面结构、文案、键盘（在 `docs/UI-DESIGN.md`） |
| `docs/UI-DESIGN.md` | **"哪里放什么"**：版面结构、侧栏、内容区、功能分层与唯一入口、文案、键盘、官方组件对照 | 颜色与档位数值（第 4 章已作废，只在 v4） |
| `docs/UI-ROADMAP.md` | **唯一施工真源的入口**：用法、决策台账（D 编号）、未决事项（Q 编号） | 数值本身——它只登记**为什么**和**分几步**，不复述值 |
| `docs/roadmap/` | 路线表的四本分册（**阶段正文的家**，2026-10-13 拆出）：`archive.md` 阶段 0–30 / `31-v4-redesign.md` / `32-gaps.md` / `cli.md` | 数值与纪律细节（各自在 `docs/UI-DESIGN-v4.md` 与 `AGENTS.md`） |
| `docs/CHANGELOG.md` | 逐轮变更记录（append-only）：某一轮到底做了什么、当时的闸与取证数 | 规则与决策（那是路线表的事） |
| `scripts/README.md` | `scripts/` 里每个脚本**证明什么、怎么跑、红的判据是哪一条**，按用途分八组，末尾一节"已知缺口" | 方法论的坑与纪律（在 `AGENTS.md`）；**它的表要与目录逐字一致**（每加/删一个脚本同一轮更新） |

⚠️ 三个"不问自明"的推论，值得写下来（都实测触发过）：
- **`docs/UI-ROADMAP.md` 是施工真源，但不是数值真源**。查一个数是多少，去
  `gui/theme.json` 或 `docs/UI-DESIGN-v4.md`；看这一个数为什么是它，才读路线表。
- **它是"入口"不是"全部"**：2026-10-13 把那份 8237 行的大文件拆成 **1 入口 + 4 分册 +
  1 变更记录**，判据是**三类读者抢一本**（改界面前要当前阶段 / 查决策要 D 条目 /
  回看要已完成阶段）。⚠️ 这与 §3 那条反向纪律不冲突——那条挡的是"为了更整齐去拆"，
  而这里拆的是**读者的时刻不同**；拆完是**完整状态**（入口那张表说得出每个阶段在哪一本，
  没有"两边各有一半"的悬空段）。
- **D / Q 的编号只在入口那份登记，正文在分册里**：查一条先看入口"决策台账"下面那张
  "编号落在哪儿"表，再按编号 grep（`grep -rn 'D92' docs/`）。**编号是别人引用它的坐标**，
  所以拆的时候只归拢、不重排（§4）。
- **`docs/UI-DESIGN.md` 是"结构"的家，不是"视觉"的家**。它的第 4、5 章已被 v4 取代
  （README 也这么写），**但正文里原来还留着整张色板和档位表**——一读就照着改。
  2026-10-12 把那两张表删了、换成一句指路。

## 2. 一条规则只允许有一个家

1. **先找家，再写。** 要记一条新规矩，先在这张表里找它是"数值 / 纪律 / 结构 / 流程"
   哪一类，写进对应的那一本。**找不到家的，按 §3 决定要不要新开一本**——
   **不要顺手写进最近刚打开的那本**。
2. **指路，不复述。** 需要提到别的家的一条规则时，写**文件名 + 小节**，
   不把值抄过来。抄一次就多一处会漂的真源，而它漂的时候**不会报错**。
   ⚠️ **引用要带文档名——编号只在本文件内有意义**：`docs/UI-DESIGN.md` §0 与
   `docs/UI-DESIGN-v4.md` §1 是**两套**铁律（界面结构 3 条 / 视觉契约 4 条），
   两边都从 1 编号 ⇒ 写「`docs/UI-DESIGN.md` §0 铁律 3」，别光写「铁律 3」。
   **2026-10-12 实锤过一次**：`gui/src/log.rs:152` 原来写的是「v4 铁律 3」，
   而它要说的是 UI-DESIGN 那第三条（同一动作一屏两个入口）——v4 的第三条是
   「不演拿不到的效果」，**编号一撞，指路就指到别人家里去了**。两套不是重复：
   真正重复的只有「不许出现裸数字」一条，现在只在 v4 §1 写全，UI-DESIGN §0
   那一份改成指路（只留"组件尺寸只用官方命名档"这半条界面侧约束）。
3. **判"统一了没有"要数"同一属性还剩几个出处"**，不是数新构件被引用了多少次。
4. **删除也是维护**：作废的表要么删、要么换成指路，**不要留着并标一句"已作废"**——
   标了也照样有人照着抄（本项目实锤过）。删掉时把那句"为什么作废"写成一句话，
   免得下一个人以为是误删又加回来。

## 3. 什么时候允许新增一本

三条**全**满足才新增；有一条不满足就写进现有的家：

- ① 它管的内容**现有任何一本都不管**（不是"目前没人写"的那种不管，是**归错了家**）；
- ② 它有**一批**规则，不是一条（只有一条就写进最接近的那一本，或加进本表）；
- ③ 能一句话说出**它的读者在什么时刻会翻它**（说不出就是没人会读的文件）。

⚠️ 反向纪律同样重要：**不要为了"更整齐"去拆已经能用的文档**。
拆分本身会制造"两边各有一半"的中间状态，而**中间状态的文档比长文档更危险**
（长文档至少是完整的）。

## 4. 路线表条目格式（编号在 `docs/UI-ROADMAP.md`，正文在 `docs/roadmap/`）

- **新条目写在哪一份**：`D` / `Q` 的**编号**永远在入口那份登记（台账 / 未决事项）；
  它的**正文**写在"动它的那个阶段"所属的分册里——哪一本问入口顶部那张分册表。
- 一条一行号：**`D<n>` 是已经定下来的决策**、**`Q<n>` 是待用户拍的问题**。
  编号只增不改，作废的条目**留着并注明被谁取代**（编号是别人引用它的坐标）。
- 每条写三段：**结论**（做了什么/定了什么）→ **为什么**（当时的证据或用户口径）→
  **连带**（还有哪一处跟着变）。
- **数值不进路线表**。写"卡间距按用户当天口径统一到 `GAP_TIGHT`"，不写"= 6"。
- **证据要能复核**：写"全站 27 处卡间带都是 6（逐段竖剖）"这种可重跑的话，
  不写"看起来就不齐"。

## 5. 改文档的操作纪律（这一条的家在 `AGENTS.md`）

**只在一个地方写**：`AGENTS.md` 的目录规则里那条 ⛔（改 `docs/*.md` 的一段只用
`Edit`，不许"读全文 → 替换 → 写全文"；改完报三个结构计数 `wc -l` /
`grep -c '^>'` / 反斜杠数；行尾不是仓库级常量）。**这里只指路，不复述**——
理由就是本文件 §2 那一条，它对本文件自己同样成立。

⚠️ 但**有一条它没写、而实操上每次都遇到**：那三个数里"引用行"和"反斜杠"两个
**必须与 `HEAD` 版并排比**，只看绝对值没意义（`docs/UI-DESIGN.md` 引用行 126、
反斜杠 65，与 `HEAD` 一模一样 = 结构没坏；只报"126"说明不了任何事）。
一次性比对用 `scripts/measure_backslash.py`（它按固定清单量），
清单外的文件用 `git show HEAD:<文件>` 与工作树各量一遍再比。

## 6. `scripts/` 的说明

`scripts/` 下有 **35 个**（34 个 `.py` + `build_installer.ps1`），职责与判据写在
**`scripts/README.md`**（2026-10-12 补上；这一节此前登记的是缺口）。它按用途分八组，
每个脚本四列：**证明什么 / 怎么跑 / 判据**，末尾一节"已知缺口"。
判据列只许两档，写死在那个文件顶部：**真闸**（判据不过就非零并点名那一条，共 12 个）
与**只报告**（不接退出码，细分"唯一非零出口是跑不起来 / 参数不足 / assert 前提"）。

⚠️ **加脚本、删脚本、改判据，同一轮就要动那张表**——它是目录的镜像，
而"表里有、目录里没有"这种漂移正是这份 README 要挡的东西。
⚠️ **不要为了整齐把脚本搬进子目录**：路径一变，`AGENTS.md` 与路线表里几十处引用全部失效。
