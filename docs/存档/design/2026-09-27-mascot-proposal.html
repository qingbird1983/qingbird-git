青鸟 Git · 吉祥物方向

从猫头身上，拆三条手法

Octocat 之所以耐看，跟"猫"关系不大——它厉害在三个可复用的构造： 单色封闭剪影、用负空间画五官、一个现实中不存在的拼接。 这三条跟物种无关，换成鸟照样成立。 下面是用这套手法做的「青鸟」推演稿，形态、曲线、内部结构全部是新的， 不临摹 Octocat 的轮廓。

1

借哪三样，不借哪一样

GitHub 那套 logo 真正值钱的是构造方法，不是猫脸。把这三条抽出来，物种可以随便换。

① 单色封闭剪影

一整块连续实心，零描边、零渐变、零内部线条。所以它能塞进 favicon、托盘、开机图标而不糊。

② 用负空间画五官

眼睛不是"画上去的黑点"，是把实心剪影挖掉的两个洞。这让它在任何底色上都成立——底色自动成为眼睛的颜色。

③ 不存在的东西

猫 + 章鱼是自然界没有的拼接，所以有记忆点。青鸟这边对应的拼接是鸟 + 提交树——尾羽分叉成 git 分支的那一笔。

不借的：Octocat 的具体轮廓

Invertocat 是 GitHub 的注册商标，Simon Oxley 的原始形象也是受版权保护的商业插画。 这份稿子只沿用上面三条构造方法，不复制它的耳朵形状、触须排布、脸型比例， 也不使用 GitHub 的近黑色 #181717。青鸟的配色走界面主色 #0D9488。

顺带说一句来源：Octocat 最早的原型是 Simon Oxley 2008 年卖给 GitHub 的 stock art， 2013 年品牌刷新时 GitHub 把它简化成了现在这个扁平单色的 Invertocat。 这次演化思路跟那次刷新是同一个路数——把插画压成符号。

稿中形态是按构造逻辑推演的几何稿，曲线还需要一轮美术细化才能定稿。 这不影响方向判断——先定方向，曲线后面再磨。

放进界面

吉祥物路线的隐藏收益：它不只当 logo，还能长出一整套资产。

4

和几何方案的关系

这其实不是"两个 logo 备选"，是两种气质。值得想清楚要哪一种。

几何流（方案 A 环中枝）

像什么：像一台仪器。冷静、精确、克制，所有元素都是功能的一部分。

气质：效率工具。用户来这里是为了干活，不是为了玩。

能长出的资产：基本只有 logo 本身，最多加个 loading 动画。

吉祥物流（方案 D/E/F 青鸟）

像什么：像一个角色。亲切、有记忆点，用户会记住它。

气质：有人味的工具。降低"我又要把代码推上去"的心理门槛。

能长出的资产：空态插画、启动动画、社区头像、关于页、周边。

其实可以都要。界面上用几何流保持效率感（这也是新布局的主轴）， logo 这一处破例用吉祥物——就像 VS Code 用代码括号做图标、GitHub 用猫， 都是"在一个纯工具的界面里给品牌留一个角色"。破例一次才有彩蛋感，破例多处就变幼稚。

5

拍板

1

要不要从几何流切到吉祥物流？

如果切，我建议 D 负形青鸟做主 logo（20px 稳、有底、任意背景成立），E 或 F 只在空态和关于页出现。如果你更想要纯工具感，A 环中枝仍然是更好的选择——它的优势是和新界面里同步环完全同构。

建议：切，用 D；几何流退到界面内部语言
2

要不要走 F 的"双尺寸版本"？

衔枝那一笔是大尺寸下的彩蛋，小尺寸必须砍。等于是每个尺寸要维护一份路径，gen-icons.mjs 会多一个尺寸分支。收益是"叼着提交线"这个梗有人会注意到。

建议：先不做 F，主 logo 用 D；空态可以用 F 的大图版本
3

下一步做不做美术细化？

稿里是按构造逻辑推演的几何形，曲线还是工程味的。真正好看要有人手调一轮——冠羽的弧度、尾羽的粗细递进、喙的转折。gen-icons.mjs 是程序化生成，能接受手写的 Bézier 控制点。
