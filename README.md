# 青鸟 Git（qingbird-git）

本地 Git 仓库一键同步工具：检测云端更新、一键拉取、一键推送，内置**无感代理回退**（针对 GitHub 网络环境）。

界面是 **Rust 原生**（[gpui-kit](https://github.com/longbridge/gpui-component) 0.7 / GPUI），业务逻辑是独立的一个 crate，两层之间不认识对方。

## 功能

* **仓库管理**：添加过的仓库持久化记忆（按最后使用排序），下次启动自动加载；移除仅删记录，不动磁盘文件。
* **多种添加方式**：文件夹选择、**拖拽文件夹进窗口**、**粘贴仓库地址克隆**（自动解析仓库名并加入管理列表）。
* **GitHub / Gitee 双平台**：界面按远端地址显示平台徽标；Gitee 等国内源通常直连即可，无需代理。
* **检测云端更新**：`git fetch` 后显示当前分支、领先/落后提交数。
* **一键拉取**：`git pull --ff-only`；本地有未提交变更时**自动**先 `stash push -u`（连未跟踪
  文件一起收走）、拉完收尾再 `pop`——收尾那一步不参与「停止」，不然中途按停会把文件留在
  暂存里。过程**实时显示进度**（接收对象百分比等），完成后展示**本次同步内容**
  （新提交列表 + 文件变更摘要）。
  ⚠️ **它不会先问你**（老 Tauri 版那句"先询问"到这一版没接，界面里那条询问分支从来不会被走到）；
  而且**暂存清单目前没有界面入口**——万一 `pop` 失败，那些文件得用命令行 `git stash list` 才找得回来。
  这两条都登记在路线表阶段 32。
* **一键推送**：无上游分支时自动 `push -u origin HEAD`；远端领先时提示先拉取。
* **分叉恢复**：本地与云端各走各的时，给变基向导（自动备份本地提交、可撤销），**不自动改写历史**。
* **磁盘占用**：递归算出仓库多大、一级目录构成；**只读目录树**点一下扫下一层；标出可安全删除的构建缓存，支持**逐项清理**与**一键清理**（先过确认框，框里逐项列清删什么、放多少）。
* **常用命令**：每个仓库四个固定槽位（开发运行 / 编译构建 / 测试 / 安装），逐仓库记。
  仓库头**常显前两颗**（开发运行、编译构建），测试与安装走 ⌘K；编辑弹窗里每槽都能就地「启动」一次。
  ⚠️ **用户钉住的自定义命令目前只出现在 ⌘K 里**，没有像四个固定槽位那样摆到仓库头上
  （`store.rs` 里那句"钉在操作区"的注释说的不是现状，已登记）。
* **⌘K 命令面板**：五个分组（切到仓库 / 当前仓库 / 批量同步 / 切换视图 / 低频动作），
  是唯一一个"不用鼠标也能干活"的入口。
* **批量同步**：拉取全部 / 推送全部 / 检测全部三条固定命令，**按已扫状态自动筛**
  （「拉取全部」只跑落后的、「推送全部」只跑非第三方且有待推送的），回车即跑不弹确认。
  脏工作区的仓库**跳过并记进它自己的日志**，不替你 stash。
  ⚠️ 批量是**最多 4 路并发**（`sync::MAX_CONCURRENT_OPS`，完成一颗补一颗）；互斥的粒度是
  **每仓库一把锁**（`sync::try_begin_op(path)`），配置写另有自己那把串行闸 `store::SAVE_LOCK`。
  旧版那句"整个应用一把锁、下沉登记在阶段 32"是 **32-8 / 32-9 之前**的形状，那两个阶段已经落了。
* **后台自动同步**：按间隔或每日定时两种档，到期自动检测并推送结果。
* **托盘常驻**：关闭主窗口后进程留在托盘，托盘菜单支持重新打开、扫描全部仓库、退出。
* **关窗时问一句**：三档可选（最小化到托盘 / 直接退出 / 每次询问），询问那一档是面板里
  三个按钮，走的是系统 `WM_CLOSE` 那条路，托盘再点能唤回同一个窗口。
* **明暗主题**：**亮色 / 暗色两档**，标题栏与设置里都能切，配置持久化。
  ⚠️ **没有「跟随系统」**：老配置里那个 `system` 值这一版从来不认，认不出的一律落浅色。
* **界面字号**：小 / 中 / 大**三档整套换**（含标题栏、卡片、表格与官方按钮），
  行高与胶囊高度都是字号的函数，所以换档不会切字。
* **快捷键可自定义**：设置里那一页能改键、能解绑、能单项恢复，顶部一键恢复默认；
  界面上的键位提示是**从 keymap 现查的**，改了键不会说谎。
* **启动秒开**：仓库列表、体积、状态都有一份 SQLite 缓存，启动先灌缓存再刷选中的那一个仓库；
  库打不开、表损坏、磁盘满一律降级，一次都不 panic。每次同步的结论**逐仓库落进操作历史**，
  日志卡那句「上次拉取 成功 · 刚刚」就是它。
* **说明页中英切换**：仓库自己的 `README` / `README.zh-CN` 两份在「说明」页签里整篇渲染，
  正文里的链接按四类分别处理（站内锚点 / 同仓库文档 / 远端页面 / 图片）。
* **第三方仓库「多出来的文件」清理**：未跟踪的删掉、已跟踪的被改过的还原回 `HEAD`，
  勾选项逐条确认，路径越界会被挡（只在仓库目录内动手）。
* **拖放按你正看着的那一组归**：在「第三方仓库」页拖进来就进第三方，落点提示卡上会写清进哪一组。
* **无感代理**：网络操作先直连，失败时自动探测本机代理并仅对当次 git 命令注入代理环境变量重试，**不修改系统代理、不影响其他软件**。探测顺序：手动指定 → 上次成功缓存 → Windows 系统代理 → 常见端口（7897 / 7890 / 7891 / 10808 / 10809 / 2080 / 8889 / 1080 / 8118）。
  ⚠️ **会改仓库的操作（拉取 / 推送 / 克隆）一律只走一条路**：并行试两条等于让两个 git
  同时写同一个仓库，实测会撞 ref 锁。只有不落地的只读命令才允许两条并行赛跑。

## 依赖

* Rust 工具链（cargo）
* Git for Windows（git CLI 与凭证管理器在 PATH 中）
* 中文字体：⚠️ **当前用系统默认字体**。设计目标是 Noto Sans SC + Sarasa Gothic SC，
  而**「启动时显式注册 TTF」这一步从来没做**（`gui/theme.json` 里只有 `font.size` 与
  `mono_font.size` 两个数值，没有字体家族这一格，代码里也没有注册入口）——
  已登记在路线表阶段 32。连带后果：**挂等宽字体的容器里放中文会掉字重**，
  所以日志输出流、patch、命令输出那几块的中文目前靠系统回退撑着的

| `crates/core/` | 业务逻辑（git 子进程封装、网络编排、仓库读写、同步、克隆、磁盘扫描、定时器、配置持久化）。**纯 Rust，不认识 gpui** |

| `docs/UI-DESIGN.md` | 设计规范：版面结构 / 侧栏 / 内容区 / 功能分层与唯一入口 / 文案 / 键盘 / 官方组件对照——**"哪里放什么"这一层仍然有效**；它的第 4、5 章（颜色与交互状态）已被 v4 取代 |
| `docs/CODE.md` | **代码规范**：文件与函数尺寸、命名、错误处理、日志、注释、提交信息、依赖 |

## 开发

```bash
cargo check --workspace                      # 类型检查（出口要求：零错零警）
cargo build --workspace                      # 编译（调试产物）
target\debug\qingbird-git.exe                # 跑起来

cargo build --workspace --release            # 发布产物（gpui 那棵树约 5 分半，约 32 MB）
pwsh scripts/build_installer.ps1             # 出安装包（顺带编 release）→ dist\qingbird-git-Setup-<版本号>.exe
```

⚠️ **debug 与 release 是两条产物路径，而且行为不同**：debug 保留控制台（panic 栈、
`eprintln!` 诊断都看得见），release 是纯 GUI 子系统、**没有 stderr**——那一路的异常
写进 `%APPDATA%\com.qingbird.git\app.log`。所以**发布前至少跑一次 debug 构建**，
有些问题只在 debug 报（`debug_assert!` 在 release 下是空操作）。
安装包不进仓库，唯一的去处是 GitHub Release 的资产。

## 测试

```bash
cargo test -p qingbird-core                  # 业务逻辑（回归靠它）
cargo test -p qingbird-gui                   # 界面里不依赖 gpui 初始化的纯逻辑
cargo test --workspace --no-run              # 测试模块也要零告警（这条 check 看不到）
python scripts/check_design_tokens.py        # 设计令牌闸：字面色值 / 裸间距 / 裸时长 / 文字冒充图标…
```

**四道闸每阶段出口都要跑**：`cargo check --workspace`、`cargo test --workspace --no-run`、
`cargo test --workspace`、`check_design_tokens.py`。最后那道挡的是编译器看不见的东西——
同一个属性有两个名字、某个数没选档。**新写的判据必须做过变异验证**（弄坏 → 见红 →
逐字节还原 → grep 查残留），只跑绿一次不算。

⚠️ 单测跑完要**核对它没往真实目录写**：本项目抓到过一次「每跑一次测试就往用户配置里
塞一条临时仓库」的事故，两周下来列表里 43 条有 40 条是垃圾，而所有闸全绿。
凡是函数名带"做一件真实的事"（init / add / save / remove）又要进单测的，
先问它末尾有没有写盘。

## 界面怎么验

GUI 只能由人眼看画面，但**「渲染出来了」和「点得动」是两道关**——
`scripts/` 里有现成工具把后者也自动化：

* `steps.py` 跑一串点击逐步抓帧（`nav` / `row` / `tab` / `click` / `wheel` / `wait` / `shot`）
* `frame.py` 放大读小字 / 几帧竖排 / 求两帧差分（**往返验证拿「逐像素相同」当判据**）
* `rowpitch.py` 逐行像素剖面量行距——**目测出来的「不齐」先量再改**
* `startup_probe.py` 按**窗口出现**为基准逐帧抓并与稳定态求差——量「打开多快就有内容」
* `uia_probe.py` / `a11y_stress.py` 当无障碍客户端，逼出平时压根不建的那棵树

**跑之前先设 `QB_APPDATA` 指向配置副本**，否则抓帧进程会读写你真实的
`%APPDATA%/com.qingbird.git/config.json`（这个坑已经踩过一次）：

```powershell
$env:QB_APPDATA = "$env:TEMP\qbapp"     # 里面放 com.qingbird.git\config.json
python scripts\steps.py "nav:105" "row:121,120" "shot:qb_a"
```

三个脚本都会在收尾时核对真实配置的指纹，**不一致就直接报出来**。

⚠️ **`steps.py` 送不进按键**（`keybd_event` 与 `PostMessageW` 都试过：窗口是前台、
鼠标点击也生效，按 `ctrl-b` 侧栏纹丝不动、逐像素差 0）⇒ **⌘K 与全部快捷键这条路
在脚本里验不到**，批量拉取/推送/检测那一整条挂在 ⌘K 上，只能你自己按。

要验「拉取成功」这类结果，合成仓库**必须配一个真远端**（本地 bare 仓库走
`file://` 即可，不联网），而且要在工作副本**克隆完之后**再往远端推一笔——
否则 ahead/behind 都是 0，点拉取是空跑，验了个寂寞。

架构与踩坑记录见 [AGENTS.md](AGENTS.md)。
