# 青鸟 Git（qingbird-git）

本地 Git 仓库一键同步工具：检测云端更新、一键拉取、一键推送，内置**无感代理回退**（针对 GitHub 网络环境）。

界面是 **Rust 原生**（[gpui-kit](https://github.com/longbridge/gpui-component) 0.7 / GPUI），业务逻辑是独立的一个 crate，两层之间不认识对方。

## 功能

* **仓库管理**：添加过的仓库持久化记忆（按最后使用排序），下次启动自动加载；移除仅删记录，不动磁盘文件。
* **多种添加方式**：文件夹选择、**拖拽文件夹进窗口**、**粘贴仓库地址克隆**（自动解析仓库名并加入管理列表）。
* **GitHub / Gitee 双平台**：界面按远端地址显示平台徽标；Gitee 等国内源通常直连即可，无需代理。
* **检测云端更新**：`git fetch` 后显示当前分支、领先/落后提交数。
* **一键拉取**：`git pull --ff-only`；本地有未提交变更时先询问，可选自动 stash → pull → pop；拉取过程**实时显示进度**（接收对象百分比等），完成后展示**本次同步内容**（新提交列表 + 文件变更摘要）。
* **一键推送**：无上游分支时自动 `push -u origin HEAD`；远端领先时提示先拉取。
* **分叉恢复**：本地与云端各走各的时，给变基向导（自动备份本地提交、可撤销），**不自动改写历史**。
* **磁盘占用**：递归算出仓库多大、一级目录构成；**只读目录树**点一下扫下一层；标出可安全删除的构建缓存，支持**逐项清理**与**一键清理**（先过确认框，框里逐项列清删什么、放多少）。
* **常用命令**：每个仓库四个固定槽位（开发运行 / 编译构建 / 测试 / 安装）+ 用户钉住的自定义命令，逐仓库记。
* **后台自动同步**：按间隔或每日定时两种档，到期自动检测并推送结果。
* **托盘常驻**：关闭主窗口后进程留在托盘，托盘菜单支持重新打开、扫描全部仓库、退出。
* **明暗主题**：亮色 / 暗色 / 跟随系统，配置持久化。
* **无感代理**：网络操作先直连，失败时自动探测本机代理并仅对当次 git 命令注入代理环境变量重试，**不修改系统代理、不影响其他软件**。探测顺序：手动指定 → 上次成功缓存 → Windows 系统代理 → 常见端口（7897 / 7890 / 7891 / 10808 / 10809 / 2080 / 8889 / 1080 / 8118）。

## 依赖

* Rust 工具链（cargo）
* Git for Windows（git CLI 与凭证管理器在 PATH 中）
* 中文字体：设计要用 Noto Sans SC + Sarasa Gothic SC，程序启动时会显式注册

## 目录

| 路径 | 内容 |
|---|---|
| `crates/core/` | 业务逻辑（git 子进程封装、网络编排、仓库读写、同步、克隆、磁盘扫描、定时器、配置持久化）。**纯 Rust，不认识 gpui** |
| `gui/` | 界面（gpui-kit 组件、五个页签、对话框、托盘） |
| `docs/UI-ROADMAP.md` | 路线表与决策台账——**改界面前先读它**，那是唯一施工真源 |
| `docs/UI-DESIGN.md` | 视觉规范 |
| `scripts/` | 实机验收用的抓帧与点击脚本 |

## 开发

```bash
cargo build --workspace              # 编译
target\debug\qingbird-git.exe        # 跑起来
```

## 测试

```bash
cargo test -p qingbird-core          # 业务逻辑（回归靠它）
cargo test -p qingbird-gui           # 界面里不依赖 gpui 初始化的纯逻辑
cargo check --workspace              # 类型检查
```

## 界面怎么验

GUI 只能由人眼看画面，但**「渲染出来了」和「点得动」是两道关**——
`scripts/` 里有现成工具把后者也自动化：

* `steps.py` 跑一串点击逐步抓帧（`nav` / `row` / `tab` / `click` / `wheel` / `wait` / `shot`）
* `frame.py` 放大读小字 / 几帧竖排 / 求两帧差分（**往返验证拿「逐像素相同」当判据**）
* `rowpitch.py` 逐行像素剖面量行距——**目测出来的「不齐」先量再改**
* `uia_probe.py` / `a11y_stress.py` 当无障碍客户端，逼出平时压根不建的那棵树

**跑之前先设 `QB_APPDATA` 指向配置副本**，否则抓帧进程会读写你真实的
`%APPDATA%/com.qingbird.git/config.json`（这个坑已经踩过一次）：

```powershell
$env:QB_APPDATA = "$env:TEMP\qbapp"     # 里面放 com.qingbird.git\config.json
python scripts\steps.py "nav:105" "row:121,120" "shot:qb_a"
```

三个脚本都会在收尾时核对真实配置的指纹，**不一致就直接报出来**。

架构与踩坑记录见 [AGENTS.md](AGENTS.md)。
